1. Solution popisuje zakladne charakteristiky MAVEN.
2. MAVEN je BUILD AUTOMATION TOOL, ktory umoznuje vykonat BUILD SW PROJECTS.
3. MAVEN je primarne vyuzivany pre BUILD JAVA TOOLS, ale MAVEN je univerzalny a je ho mozne pouzit aj napriklad pre BUILD C++ PROJECTS.
4. MAVEN pouziva na konfiguraciu PROJECT XML FILE [pom.xml]. Pre POM FILES platia nasledujuce fakty.
   A. POM FILES su XML FILES, ktore obsahuju konfiguraciu PROJECT.
   B. POM FILES sa aplikuju HIERARCHICKY. CHILD FILES su INHERETED z PARENT FILES, pricom CONFIGURATIONS su CHILD FILES su INHERETED z PARENT FILES.
   C. POM FILES BY DEFAULT pouzivaju standardnu PROJECT STRUCTURE, ktora ak je dodrzana, nie je nutna CUSTOM CONFIGURATION v POM FILE, pretoze sa aplikuju CONVENTIONS.
   D. POM FILES obsahuju DEPENDENCIES na ine PROJECTS.
   E. POM FILES obsahuju COORDINATES, ktore unikatne identifikuju dany PROJECT a ARTIFACT, ktory je z daneho PROJECT vytvoreny. MAVEN definuje nasledujuce COORINATES.
      A. COORDINATE [groupId].
      B. COORDINATE [artifactId].
      C. COORDINATE [version].
5. MAVEN pouziva na vykonavanie BUILD STEPS PLUGINS. Pre MAVEN PLUGINS platia nasledujuce fakty.
   A. MAVEN PLUGIN je zodpovedny za vykonavanie BUILD STEPS pri vykonavani BUILD daneho PROJECT.
   B. MAVEN PLUGIN moze vykonava COMPILATION daneho PROJECT, spustat UNIT TESTS, vytvarat PACKAGES ci generovat DOCUMENTATION.
   C. Kazdy MAVEN PLUGIN vykonava jeden, alebo viacero GOALS. GOAL reprezentuje TASK, ktory ma MAVEN PLUGIN vykonat.
   D. MAVEN PLUGINS mozu implementovat aj specificke DIAGNOSTIC TOOLS, ktore napriklad meraju rozlicne METRICS.
   E. MAVEN PLUGINS sa konfiguruju vo FILE [pom.xml]
   F. MAVEN umoznuje definovat CUSTOM PLUGINS, ktore mozu byt vlozene do FILE [pom.xml].
6. BUILD MAVEN PROJECT sa nazvyva MAVEN LIFECYCLE. MAVEN LIFECYCLE pozostava z postupnosti BUILD PHASES. Pre BUILD PHASES platia nasledujuce fakty.
   A. BUILD PHASES su vykonavane MAVEN PLUGINS.
   B. Kazda BUILD PHASE moze pozostavat z vykonania jedneho, alebo viacerych GOALS.
   C. DEFAULT MAVEN LIFECYCLE pozostava z nasledujucich BUILD PHASES.
      A. BUILD PHASE [VALIDATE].
      B. BUILD PHASE [COMPILE].
      C. BUILD PHASE [TEST].
      D. BUILD PHASE [PACKAGE].
      E. BUILD PHASE [VERIFY].
      F. BUILD PHASE [INSTALL].
      G. BUILD PHASE [DEPLOY].
   D. Kazda BUILD PHASE je zodpovedna za volanie vsetkych predoslych PHASES, ktore su sucastou MAVEN LIFECYCLE.
7. MAVEN riesi DEPENDENCIES pomocou MAVEN REPOSITORIES. Pre MAVEN REPOSITORIES platia nasledujuce fakty.
   A. MAVEN REPOSITORY je centralizovana COLLECTION MAVEN PROJECT, ktore su dostupne na stiahnutie pre MAVEN PROJECTS.
   B. Ak v FILE [pom.xml] je definovana DEPENDENCY, MAVEN pozera do nastavenych MAVEN REPOSITORIES, aby danu DEPENDENCY stiahol a pouzil v MAVEN LIFECYCLE.
   C. MAVEN deli MAVEN REPOSITORIES do nasledujucich kategorii.
      A. LOCAL REPOSITORY. LOCAL REPOSITORY je ulozene lokalne na pocitaci, kde sluzi ako CACHE pre MAVEN DEPENDENCIES.
      B. CENTRAL REPOSITORY. CENTRAL REPOSITORY je centralny REPOSITORY MAVEN, ktory spravuje APACHE.
      C. REMOTE REPOSITORY. REMOTE REPOSITORY je napriklad firemny REPOSITORY, ktory obsahuje DEPENDENCIES vytvorene danou firmou.
8. MAVEN podporuje MAVEN PROFILES. Pre MAVEN PROFILES platia nasledujuce fakty.
   A. MAVEN PROFILES umoznuju nastavit viacero nezavislych CONFIGURATIONS pre MAVEN LIFECYCLE v ramci jedneho FILE [pom.xml].
   B. MAVEN na zaklade ENVIRONMENTAL VARIABLES, alebo COMMAND LINE PARAMETERS umoznuje urcit, ktory MAVEN PROFILE sa pre dany MAVEN LIFECYCLE pouzije.
   C. MAVEN PROFILES sa typicky pouzivaju pre konfiguracie rozlicnych DEPLOY ENVIRONMENTS.
!!! 9. MAVEN aplikuje princip CONVENTIONS pred CONFIGURATIONS. Platia nasledujuce fakty.
   A. MAVEN definuje odporucanu strukturu MAVEN PROJECTS, ako su DIRECTORIES, ktore by mali tvorit dany PROJECT.
   B. Ak sa dodrzi odporucana struktura MAVEN PROJECTS, MAVEN nie je potrebne modifikovat, pretoze BY-CONVENTION vie, kde ma jednotlive RESOURCES hladat.
10. MAVEN je vytvoreny v JAVE a teda bezi v kazdom prostredi, kde bezi JAVA VIRTUAL MACHINE.
11. V MAVEN sa DEPENDENCIES urcuju vo FILE [pom.xml] v ELEMENT [project->dependencies].
12. MAVEN podporuje MAVEN ARCHETYPES. Pre MAVEN ARCHETYPE platia nasledujuce fakty.
   A. MAVEN ARCHETYPE umoznuje vytvorit novy PROJECT z preddefinovanej mnoziny PROJECT TEMPLATES, ktore su nazyvane ARCHETYPES.
   B. MAVEN definuje DEFAULT COLLECTION MAVEN ARCHETYPES.
   C. MAVEN umoznuje definovat vlastne ARCHETYPES.
   !!! D. PROJECT sa z MAVEN ARCHETYPE generuje pomocou COMMAND [mvn archetype:generate]. Prikladom je COMMAND [mvn archetype:generate -DarchetypeArtifactId=maven-archetype-quickstart -DgroupId=my.example -DartifactId=GeneratedFromArtifact -DinteractiveMode=false].
13. ANT je BUILD TOOL, ktory je alternativou k MAVEN. Pre ANT platia nasledujuce fakty.
   A. ANT sa povazuje za predchodcu MAVEN.
   B. ANT pouziva na BUILD daneho PROJECT XML FILE, ktory vsak obsahuje SCRIPTS, ktore ma ANT vykonat pri BUILD daneho PROJECT.
   !!! C. ANT pouziva IMPERATIVE MODEL, kde BUILD je definovany pomocou SCRIPTS. To je zasadny rozdiel oproti MAVEN, ktory striktne pouziva DECLARATIVE MODEL a pouzitie SCRIPTS NEUMOZNUJE.
   D. ANT NEOBSAHUJE moznost definovania DEPENDENCIES. DEPENDENCIES sa definuju pomocou ANT EXTENSTION APACHE IVY co komplikuje pracu s ANT.
   E. ANT sa dnes pouziva viac menej uz len na BUILD starsich PROJECTS.
14. GRADLE je BUILD TOOL, ktory je alternativou k MAVEN. Pre GRADLE platia nasledujuce fakty.
   A. GRADLE definuje vlastny DOMAIN SPECIFIC LANGUAGE pomocou, ktoreho je mozne definovat kroky potrebne pri vykonani BUILD.
   !!! B. GRADLE pouziva HYBRID MODEL, ked kombinuje DECLARATIVE MODEL podobne ako MAVEN s IMPERATIVE MODEL podobne ako ANT. GRADLE kombinuje obe tieto pristupy, takze BUILD je mozne definovat pomocou CONFIGURATIONS i SCRIPTS.
   !!! C. GRADLE podporuje INCREMENTAL BUILDS, ktore MAVEN zatial NEPODPORUJE. Vdaka INCREMENTAL BUILDS je BUILD PROCESS rychlejsi, ako je to pri MAVEN PROJECTS.
   D. GRADLE je paralelne vyvijany spolu s MAVEN a je preferovany najma pre prostredie ANDROID.
   E. GRADLE nativne podporuje riesenie DEPENDENCIES a umoznuje pristupovat k PACKAGES v MAVEN CENTRAL REPOSITORY i J-CENTER REPOSITORY.
   F. GRADLE podobne ako MAVEN sa drzi principu CONVENTION OVER CONFIGURATION. To znamena, ze DEFAULT PROJECT STRUCTURE vyzaduje iba minimalnu CUSTOMIZED CONFIGURATION, pretoze sa pouzivaju CONVENTIONS.
15. MAVEN podporuje nasledujuce BUILD LIFECYCLES.
   A. DEFAULT LIFECYCLE. Pre DEFAULT LIFECYCLE platia nasledujuce fakty.
      A. DEFAULT LIFECYCLE je PRIMARY LIFECYCLE, ktory vykonava BUILD daneho PROJECT.
      B. DEFAULT LIFECYCLE obsahuje nasledujuce PHASES.
         A. PHASE [VALIDATE].
         B. PHASE [COMPILE].
         C. PHASE [TEST].
         D. PHASE [PACKAGE].
         E. PHASE [VERIFY].
         F. PHASE [INSTALL].
         G. PHASE [DEPLOY].
   B. CLEAN LIFECYCLE. Pre CLEAN LIFECYCLE platia nasledujuce fakty.
      A. CLEAN LIFECYCLE vykonava CLEAN daneho PROJECT.
      B. CLEAN LIFECYCLE obsahuje nasledujuce PHASES.
         A. PHASE [PRE CLEAN].
         B. PHASE [CLEAN].
         C. PHASE [POST CLEAN].
   C. SITE LIFECYCLE. Pre SITE LIFECYCLE platia nasledujuce fakty.
      A. SITE LIFECYCLE generuje DOCUMENTATION daneho PROJECT.
      B. SITE LIFECYCLE obsahuje nasledujuce PHASES.
         A. PHASE [PRE SITE].
         B. PHASE [SITE].
         C. PHASE [POST SITE].
         D. PHASE [SITE DEPLOY].
16. MAVEN deli PLUGINS do nasledujucich kategorii.
   A. CORE PLUGINS. CORE PLUGINS su standardne PLUGINS, ktore su sucastou MAVEN.
   B. CUSTOM PLUGINS. CUSTOM PLUGINS su CUSTOM PLUGINS, ktore mozu byt vytvorene inymi VENDORS a mozu menit PROJECT LIFECYCLE podla specifickych potrieb.
17. MAVEN podporuje integraciu s INTEGRATED DEVELOPMENT ENVIROMENTS ako su ECLIPSE, ci INTELLIJ IDEA.
18. MAVEN PLUGIN [maven-surefire-plugin] vykonava spustanie UNIT TESTS a INTERGRATION TESTS.
19. MAVEN umoznuje vytvarat PACKAGES z PROJECTS. Pre PACKAGES platia nasledujuce fakty.
   A. MAVEN umoznuje vytvarat PACKAGES z PROJECTS.
   B. MAVEN vytvara PACKAGES v PHASE [PACKAGE] pomocou COMMAND LINE COMMAND [mvn package].
   C. MAVEN podporuje nasledujuce typy PACKAGES.
      A. PACAKGE [JAR].
      B. PACAKGE [WAR].
      C. PACAKGE [EAR].
20. MAVEN umoznuje vykonavat DEPLOYS PROJECTS. Pre DEPLOY platia nasledujuce fakty.
   A. MAVEN umoznuje vykonavat DEPLOY PROJECTS do roznych ENVIRONMENTS.
   B. MAVEN realizue DEPLOY pomocou PLUGIN [maven-deploy-plugin].
   C. MAVEN vytvara PACKAGES v PHASE [DEPLOY] pomocou COMMAND LINE COMMAND [mvn deploy].
21. MAVEN umoznuje vykonavat ANALYZE daneho PROJECT. Pre ANALYZE platia nasledujuce fakty.
   A. MAVEN umoznuje vykonavat rozne ANALYSIS daneho PROJECT.
   B. PLUGIN [maven-dependency-plugin] vykonava ANALYSIS vsetkych DEPENDENCIES, ktore PROJECT vyuziva.
   C. MAVEN DEPENDENCY ANALYSIS sa vykonava pomocou COMMAND LINE COMMAND [mvn dependency:analyze].
22. MAVEN umoznuje integraciu s CONTINUOUS INTEGRATION 
23. MAVEN umoznuje generovat DOCUMENTATION pre dany PROJECT. Pre generovanie DOCUMENTATION platia nasledujuce fakty.
   A. MAVEN umoznuje generovat DOCUMENTATION pre dany PROJECT.
   B. DOCUMENTATION je generovana pomocou PLUGIN [maven-site-plugin].
   C. MAVEN vytvara DOCUMENTATION v PHASE [SITE] pomocou COMMAND LINE COMMAND [mvn site].
   D. BY-DEFAULT DOCUMENTATION je generovana do DIRECTORY [target/site].
