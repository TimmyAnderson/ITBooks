1. Solution popisuje instalaciu a konfiguraciu MAVEN.
2. MAVEN bezi nad JAVA VIRTUAL MACHINE. To znamena, ze JAVA VIRTUAL MACHINE musi byt nainstalovana v danom OPERATING SYSTEM.
3. Instalacia MAVEN vyzaduje nasledujuce JAVA SETTINGS.
   A. Nainstalovant JAVA VIRTUAL MACHINE vo verzii vyssej ako VERSION [1.7].
   B. ENVIRONMENT VARIABLE [JAVA_HOME] musi odkazovat na instalacny DIRECTORY JAVA VIRTUAL MACHINE.
   C. ENVIRONMENT VARIABLE [PATH] musi odkazovat SUBDIRECTORY [bin] v instalacnom DIRECTORY JAVA VIRTUAL MACHINE.
4. INSTALLATION MAVEN na WINDOWS vyzaduje vykonanie nasledujucich krokov.
   A. Rozbalenie MAVEN BINARIES do DIRECTORY [MAVEN_DIRECTORY], kde VALUE [MAVEN_DIRECTORY] je lubovolny DIRECTORY.
   B. Do ENVIRONMENT VARIABLE [PATH] pridat novu VALUE [MAVEN_DIRECTORY\bin], ktora odkazuje na SUBDIRECTORY [bin] v MAVEN INSTALLATION DIRECTORY.
   C. Pridat novu ENVIRONMENT VARIABLE [M2_HOME] s VALUE [MAVEN_DIRECTORY], ktora odkazuje na MAVEN INSTALLATION DIRECTORY.
   !!! D. Skontrolovat instalaciu MAVEN pomocou COMMAND [mvn --version]. COMMAND zobrazi aj obsah ENVIRONMENT VARIABLE [JAVA_HOME] a ENVIRONMENT VARIABLE [M2_HOME], ako aj samotne verzie JAVA a MAVEN.
5. Kontrolu funkcnosti MAVEN je mozne vykonat vytvorenim noveho PROJECT a vykonanim jeho BUILD. To sa robi v nasledujucich krokoch.
   A. Novy PROJECT z ARCHETYPE sa vytvori pomocou COMMAND [mvn archetype:generate -DarchetypeArtifactId=maven-archetype-quickstart -DgroupId=my.example -DartifactId=GeneratedFromArchetype -DinteractiveMode=false].
   B. PROJECT je vytvoreny v novom SUBDIRECTORY. Prikladom je SUBDIRECTORY [GeneratedFromArchetype].
   C. V SUBDIRECTORY sa spusti COMMAND [mvn clean install], ktory vytvori BUILD MAVEN PROJECT. Ak BUILD zbehne korektne, tak MAVEN je nainstalovany spravne.
!!!!! 6. MAVEN umoznuje zapnut pre vsetky MAVEN COMMAND DETAILED LOGS pomocou OPTION [-X]. To znamena, ze COMMAND [mvn clean install -X] vykona CLEAN a INSTALL daneho PROJECT, pricom pri vykonavani COMMAND generuje rozsiahle DEBUG LOGS.
7. MAVEN umoznuje definovat LOCAL REPOSITORY. Pre LOCAL REPOSITORY platia nasledujuce fakty.
   A. LOCAL REPOSITORY je STORAGE DEPENDENCIES, ktore su ulozene v LOCAL FILESYSTEM.
   B. Do LOCAL REPOSITORY sa ukladaju DEPENDENCIES, ktore boli stiahnute pocas BUILD MAVEN PROJECTS.
   C. Pri BUILD MAVEN PROJECT MAVEN hlada najprv DEPENDENCIES v LOCAL REPOSITORY, aby ich nemusel stahovat z INTERNETU.
   D. LOCAL REPOSITORY teda sluzi ako LOCAL CACHE MAVEN DEPENDENCIES.
   !!! E. BY DEFAULT LOCAL REPOSITORY vo WINDOWS je ulozeny v DIRECTORY [C:\Users\USER_NAME\.m2\repository], kde VALUE [USER_NAME] je nazov USER NAME daneho USER, ktory pouziva MAVEN.
   !!! F. PATH k LOCAL REPOSITORY je mozne nakonfigurovat v CONFIGURATION FILE [settings.xml] v ELEMENT [localRepository].
!!! 8. MAVEN CONFIGURATION FILE [settings.xml] obsahuje SYSTEM SETTINGS pre MAVEN. MAVEN CONFIGURATION FILE [settings.xml] sa moze nachadzat v nasledujucich DIRECTORIES.
   A. GLOBAL CONFIGURATION FILE [settings.xml] je ulozeny vo WINODWS v DIRECTORY [MAVEN_DIRECTORY], kde VALUE [MAVEN_DIRECTORY\conf] je DIRECTORY, kde je nainstalovany MAVEN.
   B. PER USER CONFIGURATION FILE [settings.xml] je ulozeny vo WINODWS v DIRECTORY [C:\Users\USER_NAME\.m2], kde VALUE [USER_NAME] je nazov USER NAME po ktorym bol MAVEN instalovany.
9. MAVEN umoznuje pouzivat LOCAL REPOSITORY MANAGERS na definovanie LOCAL REPOSITORIES na urovni ENTERPRISE ENVIRONEMNTS ci jednotlivych DEVELOPER TEAMS. Pre LOCAL REPOSITORY MANAGERS platia nasledujuce fakty.
   A. LOCAL REPOSITORY MANAGER poskytuje CENTRALIZED INTERFACE pre ukladanie a ziskavanie MAVEN ARTIFACTS.
   B. LOCAL REPOSITORY MANAGER poskytuje ACCESS CONTROL a SECURITY pre jednotlivych clenov, ktori k LOCAL REPOSITORY MANAGER pristupuju.
   C. LOCAL REPOSITORY MANAGER umoznuje integrovat viacero REPOSITORIES a nad jednotlivymi ARTIFACTS vyzadovat rozne ENTERPRISE POLICIES.
   D. LOCAL REPOSITORY MANAGER umoznuje vykonavat AUDITING, REPORTING a LOGGING pri pristupe k jednotlivym ARTIFACTS.
   E. Medzi najpouzivanie LOCAL REPOSITORY MANAGERS patria tieto LOCAL REPOSITORY MANAGERS.
      A. APACHA ARCHIVA.
      B. SONATYPE NEXUS.
      C. JFROG ARTIFACTORY.
10. MAVEN CONFIGURATION FILE [settings.xml] obsahuje nasledujuce ELEMENTS.
   A. ELEMENT [localRepository] umoznuje urcit PATH k LOCAL REPOSITORY, ktora prepise DEFAULT PATH DIRECTORY [C:\Users\USER_NAME\.m2\repository], kde VALUE [USER_NAME] je nazov USER NAME daneho USER, ktory pouziva MAVEN.
   B. ELEMENT [interactiveMode] urcuje ci MAVEN ma pouzivat INTERACTIVE MODE.
   C. ELEMENT [offline] urcuje ci MAVEN ma pracovat v OFFLINE MODE.
   D. ELEMENT [proxies] umoznuje nakonfigurovat PROXY SERVERS. Ma SUBELEMENT [proxy], ktory ma nasledujuce SUBELEMENTS.
      !!! A. ELEMENT [id] je unikatne ID daneho PROXY SERVER.
      B. ELEMENT [active] urcuje ci sa PROXY SERVER ma pouzit.
      C. ELEMENT [protocol] urcuje typ PROXY SERVER PROTOCOL. Moze mat VALUE [http], alebo VALUE [https].
      D. ELEMENT [host] obsahuje HOST NAME daneho PROXY SERVER.
      E. ELEMENT [port] obsahuje PORT daneho PROXY SERVER.
      F. ELEMENT [username] obsahuje USER NAME daneho PROXY SERVER.
      G. ELEMENT [password] obsahuje PASSWORD daneho PROXY SERVER.
      H. ELEMENT [nonProxyHosts] obsahuje zoznam HOSTS NAMES, na ktore nema byt dany PROXY SERVER aplikovany. HOSTS NAMES su oddelene CHARACTER [|], alebo CHARACTER [,].
   E. ELEMENT [servers] umoznuje nakonfigurovat SERVERS ku ktorym MAVEN pristupuje. ELEMENT [servers] moze obsahovat RESPOSITORY SERVERS odkial su stahovane DEPENDENCIES, alebo kde sa ukladaju vytvorene ARTIFACTS. ELEMENT [servers] ma SUBELEMENT [server], ktory ma nasledujuce SUBELEMENTS.
      A. ELEMENT [id] je unikatne ID daneho SERVER, ktore sa pouziva vo FILE [pom.xml].
      B. ELEMENT [username] obsahuje USER NAME daneho SERVER.
      C. ELEMENT [password] obsahuje PASSWORD daneho SERVER.
      D. ELEMENT [privateKey] obsahuje PRIVATE KEY daneho SERVER.
      E. ELEMENT [passphrase] obsahuje PASS PHRASE daneho SERVER.
      F. ELEMENT [filePermissions] obsahuje POSIX PERMISSIONS pre FILES, ktore su pre dany SERVER vytvorene pri DEPLOYMENT.
      G. ELEMENT [directoryPermissions] obsahuje POSIX PERMISSIONS pre DIRECTORIES, ktore su pre dany SERVER vytvorene pri DEPLOYMENT.
   F. ELEMENT [mirrors] umoznuje nakonfigurovat MIRRORS pre REPOSITORY SERVERS. ELEMENT [mirrors] ma SUBELEMENT [mirror], ktory ma nasledujuce SUBELEMENTS.
      !!! A. ELEMENT [id] je unikatne ID daneho MIRROR. Ak MIRROR vyzaduje CREDENTIALS, musi sa VALUE zhodovat s VALUE niektoreho SERVER v ELEMENT [servers].
      B. ELEMENT [name] je FRIENDLY NAME daneho MIRROR.
      C. ELEMENT [url] je URL daneho MIRROR.
      D. ELEMENT [mirrorOf] je ID REPOSITORY, ktore je MIRRORED.
   G. ELEMENT [profiles] umoznuje nakonfigurovat PROFILES, ktore umoznuju aplikovat CUSTOM SETTINGS pri MAVEN BUILDS. ELEMENT [profiles] ma SUBELEMENT [profile], ktory ma nasledujuce SUBELEMENTS.
      !!! A. ELEMENT [id] je unikatne ID daneho PROFILE na zaklade, ktoreho je PROFILE identifikovany v COMMAND LINE COMMANDS.
      B. ELEMENT [activation] umoznuje vykonat CUSTOMIZATION BUILD ENVIRONMENT pre dany PROFILE. Umoznuje nastavit PROPERTIES ako je verzia JAVY, ci verziu OPERATING SYSTEM.
      C. ELEMENT [repositories] umoznuje definovat CUSTOM REPOSITORIES pre dany PROFILE.
      D. ELEMENT [pluginRepositories] umoznuje definovat CUSTOM PLUGIN REPOSITORIES pre dany PROFILE.
      E. ELEMENT [properties] umoznuje definovat CUSTOM KEY VALUE PROPERTIES pre dany PROFILE.
!!! 11. MAVEN PROFILE je mozne nastavit v COMMAND LINE COMMAND pomocou PARAMETER [-P]. COMMAND LINE PARAMETER [-PPROFILE_NAME] nastavuje pre dany COMMAND PROFILE na VALUE [PROFILE_NAME].
12. MAVEN umoznuje ukladat SENSITIVE DATA do CONFIGURATION FILE [settings.xml] nasledujucim sposobom.
   A. Pomocou COMMAND [mvn --encrypt-master-password MASTER_PASSWORD] sa vygeneruje ENCRYPTED MASTER PASSWORD.
   B. Vytvori sa CUSTOM CONFIGURATION FILE [settings-security.xml]. Pre FILE platia nasledujuce fakty.
      A. CONFIGURATION FILE [settings-security.xml] musi obsahovat ELEMENT [settingsSecurity]. ELEMENT [settingsSecurity] musi obsahovat ELEMENT [master]. ELEMENT [master] musi obsahovat VALUE [{ENCRYPTED_MASTER_PASSWORD}], kde VALUE [ENCRYPTED_MASTER_PASSWORD] je ENCRYPTED MASTER PASSWORD vygenerovany pomocou COMMAND [mvn --encrypt-master-password MASTER_PASSWORD].
      B. CONFIGURATION FILE [settings-security.xml] musi byt ulozeny vo WINDOWS v DIRECTORY [C:\Users\USER_NAME\.m2], kde VALUE [USER_NAME] je nazov USER NAME daneho USER, ktory pouziva MAVEN.
   C. Pmocou COMMAND [mvn --encrypt-password PASSWORD], kde VALUE [PASSWORD] je PASSWORD sa vykona ENCRYPTION daneho PASSWORD.
   D. ENCRYPTED PASSWORDS je mozne ukladat do CONFIGURATION FILE [settings.xml] vo FORMATE [{ENCRYPTED_PASSWORD}], kde VALUE [ENCRYPTED_PASSWORD] reprezentuje ENCRYPTED PASSWORD.
13. MAVEN moze byt integrovany s roznymi INTEGRATED DEVELOPMENT ENVIRONMENTS.
14. ECLIPSE ma MAVEN priamo integrovany v sebe. Platia nasledujuce fakty.
   A. ECLIPSE ma integrovany MAVEN pomocou PLUGIN [Maven Integration for Eclipse]. Platia nasledujuce fakty.
      A. PLUGIN [Maven Integration for Eclipse] je instalovany BY-DEFAULT.
      B. PLUGIN [Maven Integration for Eclipse] je mozne instalovat MANUALNE pomocou COMMAND [Help->Eclipse Marketplace...], kde sa vyhlada VALUE [Maven Integration for Eclipse].
   B. MAVEN PROJECTS je mozne importovat do ECLIPSE nasledujucim sposobom.
      A. Pomocou COMMAND [File->Import...] sa spusti IMPORT WINDOW.
      B. Z IMPORT WINDOWS sa vyberie OPTION [Maven->Existing Maven Projects].
      C. Vo FILE SYSTEM sa najde FILE [pom.xml] daneho MAVEN PROJECT.
      D. ECLIPSE vykona import daneho MAVEN PROJECT.
