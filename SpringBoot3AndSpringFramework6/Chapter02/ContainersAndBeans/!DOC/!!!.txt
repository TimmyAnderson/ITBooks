//----------------------------------------------------------------------------------------------------------------------
1. Solution popisuje SPRING COMPONENTS a SPRING MANAGED BEANS.
2. SPRING FRAMEWORK PROGRAMS vytvaraju pri starte SPRING CONTAINER. Pre SPRING CONTAINER platia nasledujuce fakty.
   A. SPRING CONTAINER je DEPENDENCNY INJECTION CONTAINER, prostrednictvom, ktoreho SPRING FRAMEWORK implementuje DEPENDENCY INJECTION.
   B. SPRING CONTAINER obsahuje OBJECTS, ktore sa nazyvaju SPRING MANAGED BEANS.
   C. SPRING CONTAINER vykonava nad SPRING MANAGED BEANS nasledujuce OPERATIONS.
      A. Vytvaranie SPRING MANAGED BEANS.
      B. Manazment SPRING MANAGED BEANS.
      C. Konfiguraciu a riesenie DEPENDENCIES medzi jednotlivymi SPRING MANAGED BEANS.
   D. SPRING MANAGED BEANS, ktore su sucastou SPRING CONTAINER pouziva SPRING FRAMEWORK na implementaciu DEPENDENCY INJECTION.
   !!! E. Nie kazdy OBJECT vytvoreny v SPRING FRAMEWORK PROGRAMS musi byt sucastou SPRING CONTAINER. LOCAL OBJECTS, ako su STRINGS, ktore sa nepouzivaju v DEPENDENCY INJECTION nie su ulozene v SPRING CONTAINER.
3. SPRING CONTAINER je implementovany prostrednictvom CLASS [SpringApplication]. Pre CLASS [SpringApplication] platia nasledujuce fakty.
   A. CLASS [SpringApplication] implementuje SPRING CONTAINER.
   B. Instanciu CLASS [SpringApplication] je mozne vytvorit nasledujucimi sposobmi.
      A. Volanim CONSTRUCTOR. Instancia CLASS [SpringApplication] sa volanim CONSTRUCTOR vytvara v nasledujucich krokoch.
         A. Zavola sa CONSTRUCTOR [SpringApplication(Class<?>... primarySources)], ktory ma ako PARAMETER CLASS TYPES, ktore obsahuju CONFIGURATION SPRING CONTAINER.
         B. Vykona sa CONFIGURATION instancie CLASS [SpringApplication] volanim jej METHODS.
         C. Zavola sa METHOD [ConfigurableApplicationContext SpringApplication.run(String... args)], ktora ma ako PARAMETER ARGUMENTS zaslane do MAIN METHOD. Tato METHOD spusti SPRING CONTAINER.
      B. Pouzitim CLASS [SpringApplicationBuilder]. Instancia CLASS [SpringApplication] sa pouzitim CLASS [SpringApplicationBuilder] vytvara v nasledujucich krokoch.
         A. Vytvori sa instancia CLASS [SpringApplicationBuilder] volanim CONSTRUCTOR [SpringApplicationBuilder(Class<?>... sources)], ktory ma ako PARAMETER CLASS TYPES, ktore obsahuju CONFIGURATION SPRING CONTAINER.
         B. Vykona sa CONFIGURATION instancie CLASS [SpringApplicationBuilder] volanim jej METHODS.
         C. Zavola sa METHOD [ConfigurableApplicationContext SpringApplicationBuilder.run(String... args)], ktora ma ako PARAMETER ARGUMENTS zaslane do MAIN METHOD. Tato METHOD spusti SPRING CONTAINER.
      C. Pouzitim STATIC METHOD [ConfigurableApplicationContext SpringApplication.run(Class<?>[] primarySources, String[] args)]. STATIC METHOD ma PARAMETER [primarySources] CLASS TYPES, ktore obsahuju CONFIGURATION SPRING CONTAINER a PARAMETER [args], ktory obsahuje ARGUMENTS zaslane do MAIN METHOD. Tato METHOD vytvori instanciu CLASS [SpringApplication] a spusti SPRING CONTAINER.
   C. Pri vykonani METHOD [ConfigurableApplicationContext SpringApplication.run(String... args)] sa mozu stat nasledujuce cinnosti.
      A. Ak sa v CONFIGURATION SPRING CONTAINER nachadza ERROR, dojde k vzniku EXCEPTION.
      B. Ak je CONFIGURATION SPRING CONTAINER v poriadku, vykonaju sa nasledujuce cinnosti.
         A. METHOD [run()] spusti SPRING CONTAINER.
         B. METHOD [run()] inicializuje vsetky nakonfigurovane SPRING MANAGED BEANS.
         !!! C. METHOD [run()] sa ukonci.
         D. Riadenie sa vrati do METHOD [main()], ktora spravidla nema ziaden dalsi CODE a hned sa ukonci.
         !!!!! E. Ak SPRING CONTAINER ma v CONFIGURATION ulozene napriklad spustenie TOMCAT WEB SERVER, METHOD [run()] ho spusti spustenim separatneho THREAD, takze aj po skonceni METHOD [main()] PROGRAM dalej pokracuje.
      C. Ak je CONFIGURATION SPRING CONTAINER v poriadku, CONFIGURATION obsahuje napriklad spustenie INTERACTIVE SHELL, alebo GUI PROGRAM, vykonaju sa nasledujuce cinnosti.
         A. METHOD [run()] spusti SPRING CONTAINER.
         B. METHOD [run()] inicializuje vsetky nakonfigurovane SPRING MANAGED BEANS.
         !!! C. METHOD [run()] sa dostane do LOOP, az kym nie je INTERACTIVE SHELL, alebo GUI PROGRAM ukonceny.
         D. Riadenie sa vrati do METHOD [main()], ktora spravidla nema ziaden dalsi CODE a hned sa ukonci.
4. METHOD [ConfigurableApplicationContext SpringApplication.run(String... args)] vracia instanciu INTERFACE [ConfigurableApplicationContext]. Pre INTERFACE [ConfigurableApplicationContext] platia nasledujuce fakty.
   A. INTERFACE [ConfigurableApplicationContext] je INTERFACE, ktory reprezentuje BEAN FACTORY umoznujuci spravu SPRING MANAGED BEANS.
   B. INTERFACE [ConfigurableApplicationContext] umoznuje vkladanie INTERNATIONALIZED RESOURCE FILES.
   C. INTERFACE [ConfigurableApplicationContext] umoznuje nacitanie RESOURCES pomocou CLASS [ResourceLoader].
   D. INTERFACE [ConfigurableApplicationContext] umoznuje zasielat a prijimat EVENTS zo SPRING CONTAINER.
   E. INTERFACE [ConfigurableApplicationContext] je DERIVED z INTERFACE [ListableBeanFactory], ktory obsahuje METHOD [String[] ListableBeanFactory.getBeanDefinitionNames()]. Tato METHOD vracia zoznam vsetkych SPRING MANAGED BEANS.
   !!! E. INTERFACE [ConfigurableApplicationContext] je DERIVED z INTERFACE [ListableBeanFactory] a to je DERIVED z INTERFACE [BeanFactory]. Tento INTERFACE definuje mnozstvo METHODS pomocou ktorych je mozne ziskat instancie SPRING MANAGED BEANS.
!!!!! 5. Zasadny rozdiel medzi SPRING FRAMEWORK PROGRAMS a SPRING BOOT PROGRAMS je, ze v SPRING FRAMEWORK PROGRAMS je nutne CONFIGURATION vsetkych SPRING MANAGED BEANS nutne vykonat manualne. V SPRING BOOT PROGRAMS pri spusteni dochadza k procesu AUTOCONFIGURATION, ked su SPRING MANAGED BEANS nakonfigurovane AUTOMATICKY.
!!!!! 6. SPRING CONTAINERS je mozne vykonavat aj MANUALNE. Pre manualne vytvaranie SPRING CONTAINERS platia nasledujuce fakty.
   A. Pri pouziti manualneho vytvarania SPRING CONTAINERS sa CLASS [SpringApplication] vobec NEPOUZIVA.
   B. Manualne vytvaranie SPRING CONTAINERS sa vykonava pomocou nasledujucich krokov.
      A. Vytvori sa instancia CLASS [AnnotationConfigApplicationContext], ktora reprezentuje SPRING CONTAINER.
      !!!!! B. Pretoze CLASS [AnnotationConfigApplicationContext] alokuje RESOURCES a implementuje INTERFACE [AutoCloseable] odporuca sa vytvaranie jej instancie uzavriet v TRY WITH RESOURCES STATEMENT.
      C. Volaju sa METHODS CLASS [AnnotationConfigApplicationContext] pomocou ktorych je mozne nakonfigurovat SPRING CONTAINER.
      !!! D. Volanim METHOD [void AnnotationConfigApplicationContext.scan(String... basePackages)] sa registruju SCAN PATHS, kde ma SPRING CONTAINER vyhladavat SPRING MANAGED BEANS.
      !!! E. Volanim METHOD [void AnnotationConfigApplicationContext.register(Class<?>... componentClasses)] sa registruju COMPONENT CLASSES reprezentujuce CONFIGURATION CLASSES, alebo jednotlive SPRING MANAGED BEANS.
      !!!!! F. Po nakonfigurovani SPRING CONTAINER je NUTNE volat METHOD [void AbstractApplicationContext.refresh() throws BeansException, IllegalStateException], aby doslo k spusteniu SPRING CONTAINER.
      G. Po zavolani METHOD [void AbstractApplicationContext.refresh() throws BeansException, IllegalStateException] je plne inicializovany a funkcny.
7. SPRING MANAGED BEANS je mozne pridavat do SPRING CONTAINERS nasledujucimi sposobmi.
   A. DEKLARATIVNE pomocou ANNOTATIONS.
   B. DEKLARATIVNE pomocou XML CONFIGURATION FILE.
   C. MANUALNE v CODE.
8. SPRING MANAGED BEANS je mozne pridavat do SPRING CONTAINERS pomocou ANNOTATION [@Configuration]. Pre ANNOTATION [@Configuration] platia nasledujuce fakty.
   A. ANNOTATION [@Configuration] je SPRING FRAMEWORK ANNOTATION, a NIE SPRING BOOT ANNOTATION.
   B. ANNOTATION [@Configuration] moze byt aplikovana na TYPES.
   C. ANNOTATION [@Configuration] je pristupna v RUNTIME pomocou REFLECTION.
   D. ANNOTATION [@Configuration] vykonava nasledujucu cinnost.
      A. SPRING BOOT AUTOMATICKY pridava SPRING MANAGED BEANS oznacene pomocu ANNOTATION [@Configuration] do SPRING CONTAINERS. Podmienkou je, aby SPRING MANAGED BEANS boli ulozene v istom PACKAGE v akom sa nachadza MAIN CLASS, alebo v jeho CHILD PACKAGES.
      !!! B. SPRING BOOT AUTOMATICKY NEPRIDAVA do SPRING CONTAINERS SPRING MANAGED BEANS, ktore sice su oznacene pomocu ANNOTATION [@Configuration], ale sa nenachadzaju v tom istom PACKAGE v akom sa nachadza MAIN CLASS, alebo v jeho CHILD PACKAGES. Tieto PACKAGES je treba pridat PROGRAMOVO do CLASS PATH, aby boli automaticky vlozene do SPRING CONTAINERS.
9. SPRING BOOT pridava TYPES oznacene pomocou ANNOTATION [@Configuration] do SPRING CONTAINERS, pretoze na MAIN CLASS je aplikovany ANNOTATION [@SpringBootApplication]. Pre ANNOTATION [@SpringBootApplication] platia nasledujuce fakty.
   A. ANNOTATION [@SpringBootApplication] moze byt aplikovana na TYPES.
   B. ANNOTATION [@SpringBootApplication] je pristupna v RUNTIME pomocou REFLECTION.
   !!! C. ANNOTATION [@SpringBootApplication] ma aplikovanu ANNOTATION [@ComponentScan], ktora vykonava COMPONENT SCAN v istom PACKAGE v akom sa nachadza MAIN CLASS, alebo v jeho CHILD PACKAGES.
10. SPRING BOOT AUTOMATICKY pridava SPRING MANAGED BEANS v nasledujucich krokoch.
   A. Pri spusteni MAIN CLASS sa vytvori SPRING CONTAINER.
   B. SPRING CONTAINER spusti SCAN vsetkych SPRING MANAGED BEANS v definovanych PACKAGES.
   C. Pre kazdy najdeny SPRING MANAGED BEAN je vytvorena jeho instancia.
   D. Instancie SPRING MANAGED BEANS su pridane do SPRING CONTAINER.
11. SPRING BOOT definuje aj dalsie ANNOTATIONS na definovanie SPRING MANAGED BEANS. Platia nasledujuce fakty.
   A. SPRING BOOT definuje nasledujuce ANNOTATIONS na definovanie SPRING MANAGED BEANS.
      A. ANNOTATION [@Controller]. Semnaticky ANNOTATION oznacuje SPRING MANAGED BEAN, ktory sluzi ako CONTROLLER, ktory vystavuje WEB API ENDPOINT.
      B. ANNOTATION [@Service]. Semnaticky ANNOTATION oznacuje SPRING MANAGED BEAN, ktory sluzi ako SERVICE, ktore realizuje BUSINESS LOGIC.
      C. ANNOTATION [@Repository]. Semnaticky ANNOTATION oznacuje SPRING MANAGED BEAN, ktory sluzi ako REPOSITORY, ktore realizuje DB OPERATIONS.
   B. Pre ANNOTATIONS platia nasledujuce fakty.
      A. ANNOTATIONS mozu byt aplikovane na TYPES.
      !!! B. ANNOTATIONS su COMPOSITE ANNOTATIONS, ktore preberaju ANNOTATION [@Component].
   !!! C. SPRING BOOT umoznuje definovat CUSTOM ANNOTATIONS, na ktore ak je aplikovana ANNOTATION [@Component], tak danu ANNOTATION je mozne pouzit na oznacenie SPRING MANAGED BEANS.
12. SPRING BOOT vyzaduje, aby do SPRING CONTAINER bola zaslana START CONFIGURATION. Pre START CONFIGURATION platia nasledujuce fakty.
   A. START CONFIGURATION je zasialana vo forme CONFIGURATION CLASSES. Pre CONFIGURATION CLASS platia nasledujuce fakty.
      A. CONFIGURATION CLASS obsahuje CONFIGURATION SPRING PROGRAM.
      !!! B. CONFIGURATION CLASS MUSI byt oznacena pomocou ANNOTATION [@Configuration], alebo pomocou ANNOTATION [@Component]. Vynimkou je iba START CONFIGURATION, ktora NEMUSI byt oznacena pomocou tychto ANNOTATIONS.
      !!!!! C. START CONFIGURATION NEMUSI byt oznacena pomocou ANNOTATION [@Configuration], alebo pomocou ANNOTATION [@Component]. Je to preto, lebo START CONFIGURATION je zasielana priamo do SPING BOOT bud do CONSTRUCTOR CLASS [SpringApplication], alebo do METHODS [SpringApplication.run()]. A tym padom JAVA AUTOMATICKY poklada START CONFIGURATION CLASS za CONFIGURATION CLASS, aj ked NIE je oznacena pomocou ANNOTATION [@Configuration], alebo pomocou ANNOTATION [@Component].
   B. CONFIGURATION CLASSES su zasielane do SPRING BOOT nasledujucimi sposobmi.
      A. Ako PARAMETERS do CONSTRUCTOR CLASS [SpringApplication(Class<?>... primarySources)].
      B. Ako PARAMETER do METHOD [ConfigurableApplicationContext SpringApplication.run(Class<?> primarySource,, String... args)].
      C. Ako PARAMETERS do METHOD [ConfigurableApplicationContext SpringApplication.run(Class<?>[] primarySources, String[] args)].
   C. BY-DEFAULT ako CONFIGURATION CLASS je pouziva MAIN CLASS.
   !!! D. MAIN CLASS je BY-DEFAULT oznacena pomocou ANNOTATION [@SpringBootApplication].
   !!! E. ANNOTATION [@SpringBootApplication] je COMPOSITE ANNOTATION, ktora je oznacena pomocou ANNOTATION [@SpringBootConfiguration].
   !!!!! F. ANNOTATION [@SpringBootConfiguration] je COMPOSITE ANNOTATION, ktora je oznacena pomocou ANNOTATION [@Configuration]. Takymto sposobom je na MAIN CLASS BY-DEFAULT applikovana ANNOTATION [@Configuration], co z nej robi CONFIGURATION CLASS.
13. COMPONENT SCAN je mechanizmus umoznujuci SPRING BOOT automaticke vyhladavanie SPRING MANAGED BEANS. Pre COMPONENT SCAN platia nasledujuce fakty.
   A. COMPONENT SCAN umonzuje automaticky vyhladavanie SPRING MANAGED BEANS v FILE SYSTEM daneho PROJECT.
   B. COMPONENT SCAN je logickou sucastou SPRING BOOT a umoznuje SPRING BOOT automaticku konfiguraciu SPRING MANAGED BEANS.
   C. COMPONENT SCAN sa realizuje pomocou ANNOTATION [@ComponentScan].
   !!!!! D. COMPONENT SCAN sa vykonava v nasledujucich krokoch.
      A. COMPONENT SCAN pouzije ELEMENT [String[] basePackages] a ELEMENT ELEMENT [Class<?>[] basePackageClasses] na urcenie, BASE PACKAGES. Ak ELEMENT [String[] basePackages] a ELEMENT ELEMENT [Class<?>[] basePackageClasses] NIE su definovane, ako BASE PACKAGE sa pouzije PACKAGE v ktorej je CLASS s aplikovanou ANNOTATION [@ComponentScan] definovana.
      !!! B. COMPONENT SCAN sa vykonava nielen v BASE PACKAGES, ale aj vo vsetkych CHILD PACKAGES danych BASE PACKAGES.
      C. COMPONENT SCAN prechadza vsetkych TYPES, ktore sa nachadzaju v BASE PACKAGES a CHILD PACKAGES a vykonava pre ne nasledujuce cinnosti.
         !!! A. Pre TYPE zavola vsetky EXCLUDE FILTERS, ktore su definovane v ELEMENT [ComponentScan.Filter[] excludeFilters]. Ak niektory EXCLUDE FILTER vrati VALUE [true], TYPE je ignorovany, a NIE je zaradeny do SPRING CONTAINER ako SPRING MANAGED BEAN.
         !!! B. Pre TYPE zavola vsetky INCLUDE FILTERS, ktore su definovane v ELEMENT [ComponentScan.Filter[] includeFilters]. Ak niektory INCLUDE FILTER vrati VALUE [true], TYPE je zaradeny do SPRING CONTAINER ako SPRING MANAGED BEAN.
      !!!!! D. BY-DEFAULT ma ANNOTATION [@ComponentScan] nastaveny ELEMENT [useDefaultFilters] na VALUE [true]. V takomto pripade DEFAULT INCLUDE FILTER vklada vsetky TYPES, na ktore je aplikovana ANNOTATION [@Component], ci niektora z jej CHILD ANNOTATIONS.
14. Pre ANNOTATION [@ComponentScan] platia nasledujuce fakty.
   A. ANNOTATION [@ComponentScan] moze byt aplikovana na TYPES.
   B. ANNOTATION [@ComponentScan] je pristupna v RUNTIME pomocou REFLECTION.
   C. ANNOTATION [@ComponentScan] je oznacena pomocou ANNOTATION [@Repeatable] co znamena, ze moze byt aplikovana viackrat na ten isty TYPE.
   D. ELEMENT [String[] basePackages] umoznuje definovat BASE PACKAGES. Platia nasledujuce fakty.
      !!! A. ELEMENT [String[] basePackages] definuje zoznam BASE PACKAGES. COMPONENT SCAN vykonava vyhladavanie SPRING MANAGED BEANS v tychto PACKAGES, ako aj vo vsetkych CHILD PACKAGES tychto PACKAGES.
      B. Jeden BASE PACKAGE moze definovat aj viacero BASE PACKAGES, ktore su oddelene pomocou SEPARATORS ako su WHITESPACES, COMMAS, alebo SEMICOLLONS.
      C. Ak je ELEMENT [String[] basePackages] pre ANNOTATION [@ComponentScan] explicitne nastaveny, potom ANNOTATION [@ComponentScan] nevykonava COMPONENT SCAN v PACKAGE v ktorom je TYPE s aplikovanou ANNOTATION [@ComponentScan] definovany.
      D. ELEMENT je ALIAS k ELEMENT [value].
   E. ELEMENT [Class<?>[] basePackageClasses] umoznuje definovat BASE PACKAGES CLASSES. Platia nasledujuce fakty.
      !!! A. ELEMENT [Class<?>[] basePackageClasses] definuje zoznam CLASSES, ktore urcuju, ktore v ktorych PACKAGES sa bude vykonavat COMPONENT SCAN. Plati, ze COMPONENT SCAN sa vykonava v PACKAGE v ktorom je dana CLASS definovana a takisto vo vsetkych CHILD PACKAGES.
      B. Pouzitie ELEMENT [Class<?>[] basePackageClasses] je bezpecnejsie oproti pouzitiu ELEMENT [String[] basePackages], ze ELEMENT [Class<?>[] basePackageClasses] pouziva CLASSES namiesto STRINGS a tym padom pri premenovani PACKAGE nedojde k vzniku nekompabilit.
   F. ELEMENT [boolean useDefaultFilters] urcuje ci do zoznamu FILTERS maju byt pridane DEFAULT FILTERS.
   G. ELEMENT [ComponentScan.Filter[] includeFilters] umoznuje definovat INCLUDE FILTERS. INCLUDE FILTERS urcuju, ktore TYPES maju byt vlozene do SPRING CONTAINER ako SPRING MANAGED BEANS.
   H. ELEMENT [ComponentScan.Filter[] excludeFilters] umoznuje definovat EXCLUDE FILTERS. EXCLUDE FILTERS urcuju, ktore TYPES NEMAJU byt vlozene do SPRING CONTAINER ako SPRING MANAGED BEANS.
15. Pre ANNOTATION [@ComponentScan.Filter] platia nasledujuce fakty.
   A. ANNOTATION [@ComponentScan.Filter] umoznuje definovat CUSTOM FILTERS, ktore sa aplikuju pri COMPONENT SCAN.
   B. ANNOTATION [@ComponentScan.Filter] je INNER ANNOTATION ANNOTATION [@ComponentScan].
   C. ANNOTATION [@ComponentScan.Filter] je pristupna v RUNTIME pomocou REFLECTION.
   D. ELEMENT [Class<?>[] classes] definuje zoznam CLASSES, na ktore ma byt aplikovany FILTER.
   E. ELEMENT [String[] pattern] definuje SEARCH PATTERN, ktory sa aplikuje na FILTER NAMIESTO ELEMENT [Class<?>[] classes].
   F. ELEMENT [FilterType type] definuje TYPE daneho FILTER.
16. ENUM [FilterType] definuje FILTER TYPE. ENUM ma nasledujuce VALUES.
   A. VALUE [ANNOTATION] znamena, ze FILTER sa aplikuje na TYPES, ktore maju definovanu danu ANNOTATION, alebo niektoru z CHILD ANNOTATIONS.
   !!! B. VALUE [ASSIGNABLE_TYPE] znamena, ze FILTER sa aplikuje na TYPES, ktore je mozne priradit do definovanych TYPES pomocou OPERATOR [instanceof].
   C. VALUE [ASPECTJ] znamena, ze FILTER sa aplikuje na TYPES, ktorych nazov splna ASPECTJ EXPRESSION.
   D. VALUE [REGEX] znamena, ze FILTER sa aplikuje na TYPES, ktorych nazov splna REGEX EXPRESSION.
   !!! E. VALUE [CUSTOM] znamena, ze FILTER vola CUSTOM FILTER TYPE [TypeFilter] METHOD [boolean match(MetadataReader MetadataReader, MetadataReaderFactory MetadataReaderFactory) throws IOException], ktora ak vrati VALUE [true] tak FILTER je na dany TYPE aplikovany.
!!! 17. COMPONENT SCAN umoznuje definovat CUSTOM FILTERS. Platia nasledujuce fakty.
   A. Definuje sa CUSTOM TYPE, ktory implementuje INTERFACE [TypeFilter].
   B. INTERFACE [TypeFilter] ma METHOD [boolean match(MetadataReader MetadataReader, MetadataReaderFactory MetadataReaderFactory) throws IOException], ktoru vola FILTER pre urcenie ci na dany TYPE ma byt FILTER aplikovany, alebo nie.
   !!!!! C. PARAMETER TYPE [MetadataReader] a PARAMETER TYPE [MetadataReaderFactory] umoznuju kontrolu lubovolnej casti metadat daneho TYPE. To znamena, ze CUSTOM FILTER moze napriklad vyberat tie TYPES, ktore maju implementovane specificke BASE TYPES, INTERFACES, CONSTRUCTORS, ci METHODS.
   D. Definuje sa CUSTOM FILTER, ktory musi mat nasledujuce nastavenia.
      A. ELEMENT [FilterType type] musi obsahovat VALUE [CUSTOM].
      B. ELEMENT [Class<?>[] classes] musi obsahovat CUSTOM FILTER TYPE.
18. SPRING FRAMEWORK umoznuje vytvarat SHELL PROGRAMS. Pre SHELL PROGRAMS platia nasledujuce fakty.
   A. SHELL PROGRAM je INTERAKTIVNY PROGRAM, ktory umoznuje interakciu s USERS bud pomocou CONSOLE USER INTERFACE, alebo pomocou GRAPHICAL USER INTERFACE.
   B. SHELL PROGRAMS su implementovane pomocou DEPENDENCY [spring-shell-starter].
   !!!!! C. Ak je do SPRING BOOT PROJECT vlozena DEPENDENCY [spring-shell-starter], PROGRAM sa automaticky stava SHELL PROGRAMOM. To znamena nasledujuce.
      A. V METHOD [SpringApplication.run()] je spusteny CONSOLE USER INTERFACE.
      !!! B. METHOD [SpringApplication.run()] je BLOCKED az kym CONSOLE USER INTERFACE nie je ukonceny.
   D. DEFAULT CONSOLE USER INTERFACE podporuje nasledujuce COMMANDS.
      A. COMMAND [help]. COMMAND zobrazi HELP TEXT.
      !!! B. COMMAND [exit]. COMMAND ukonci SHELL a vykona sa CODE za METHOD [SpringApplication.run()].
   !!!!! E. Z ECLIPSE NIE JE mozne spustat SHELL PROGRAMS. Je ich mozne spustat IBA z CONSOLE.
19. Do SHELL PROGRAMS je mozne pridavat nove COMMANDS nasledujucim sposobom.
   A. Definuje sa CUSTOM CLASS, ktora je oznacena pomocou ANNOTATION [@Component].
   !!! B. V CUSTOM CLASS sa pre kazdy COMMAND definuje METHOD, ktora je oznacena ANNOTATION [@Command]. Ak ANNOTATION [@ShellMethod] pouzije ELEMENT [String[] name] jeho VALUE definuje COMMAND NAMES. Ak sa ELEMENT [String[] name] NEPOUZIJE, COMMAND NAME je odvodeny z nazvu METHOD.
   C. Po pridani novej COMMAND je COMMAND mozne zobrazit pomocou COMMAND [help].
   D. COMMAND moze mat PARAMETERS, ktore sa prenasaju ako METHOD PARAMETERS do COMMAND METHOD. Tieto METHOD PARAMETERS MUSIA byt oznacene pomocou ANNOTATION [@Option]. PARAMETERS, ktore obsahujuju WHITESPACES MUSIA byt uzatvorene pomocou CHARACTERS ["VALUE"], kde VALUE [VALUE] je VALUE WHITESPACES.
   !!! E. COMMAND METHOD moze vratit lubovolnu RETURN VALUE, ktora je zobrazena ako vystup COMMAND v SHELL PROGRAM.
   F. COMMAND METHOD moze vykonavat lubovolnu cinnost ako je napriklad vypis do CONSOLE, ci ine operacie.
20. Pre ANNOTATION [@Command] platia nasledujuce fakty.
   A. ANNOTATION umoznuje definovat METHOD, ktora sa vykona ako COMMAND v SHELL PROGRAM.
   B. ANNOTATION moze byt aplikovana na METHODS.
   C. ANNOTATION je pristupna v RUNTIME pomocou REFLECTION.
   D. ELEMENT [String group] urcuje GROUP do ktorej COMMAND patri.
   !!! E. ELEMENT [String[] name] urcuje COMMAND NAMES pomocou ktorych je COMMAND vyvolany. Ak tento ELEMENT NIE je nastaveny, tak sa ako COMMAND NAME pouziva nazov METHOD v KEBAB CASE.
   F. ELEMENT [String description] obsahuje COMMAND DESCRIPTION, ktory je zobrazovany pri zavolani COMMAND [help].
21. Pre ANNOTATION [@Option] platia nasledujuce fakty.
   A. ANNOTATION umoznuje oznacit METHOD PARAMETER, ktory ma byt do METHOD zaslany ako PARAMETER daneho COMMAND.
   B. ANNOTATION moze byt aplikovana na METHOD PARAMETERS.
   C. ANNOTATION je pristupna v RUNTIME pomocou REFLECTION.
   D. ELEMENT [char shortName] definuje SHORT NAME daneho COMMAND.
   E. ELEMENT [String longName] definuje LONG NAME daneho COMMAND.
   F. ELEMENT [String description] definuje DESCRIPTION daneho COMMAND.
   G. ELEMENT [String defaultValue] definuje DEFAULT VALUE daneho COMMAND.
   H. ELEMENT [boolean required] definuje ci COMMAND je REQUIRED.
22. SPRING FRAMEWORK podporuje nasledujuce CONCEPTS.
   A. INVERSION OF CONTROL. Pri INVERSION OF CONTROL nie su OBJECTS vytvarane priamo v CODE daneho PROGRAMU, ale vytvara ich FRAMEWORK, v ktorom PRORGRAM bezi a nasledne ich vklada do CODE.
   B. DEPENDENCY INJECTION. Pri DEPENDENCY INJECTION su DEPENDENT OBJECTS vytvarane FRAMEWORK a automaticky vkladane do COMPONENTS.
23. SPRING FRAMEWORK realizuje DEPENDENCY INJECTION nasledujucimi sposobmi.
   A. CONSTRUCTOR INJECTION. Pre CONSTRUCTOR INJECTION platia nasledujuce fakty.
      A. Pri CONSTRUCTOR INJECTION je DEPENDENT OBJECT vlozeny SPRING FRAMEWORK do CLASS volanim CONSTRUCTOR s nastavenym CONSTRUCTOR PARAMETER. CONSTRUCTOR moze CONSTRUCTOR PARAMETER vlozit do FIELD pre dalsie pouzitie.
      B. CONSTRUCTOR INJECTION sa aplikuje iba na TYPES, ktore su SPRING MANAGED BEANS a na TYPES.
      C. PARAMETERS CONSTRUCTOR INJECTION musia byt tiez SPRING MANAGED BEANS.
      !!! D. CONSTRUCTOR na ktory sa ma aplikovat CONSTRUCTOR INJECTION MUSI byt oznaceny pomocou ANNOTATION [@Autowired]. No ak ma TYPE iba 1 CONSTRUCTOR, tento NEMUSI byt oznaceny ANNOTATION [@Autowired] a SPRING FRAMEWORK ho AUTOMATICKY zavola pre CONSTRUCTOR INJECTION.
      E. Pouzitie CONSTRUCTOR INJECTION umoznuje nastavit FIELD, do ktoreho sa uklada SPRING MANAGED BEAN pomocou KEYWORD [final].
      !!! F. Pouzitie CONSTRUCTOR INJECTION vytvara zavislost jedneho SPRING MANAGED BEAN na inom a SPRING FRAMEWORK musi pri vytvarani SPRING CONTAINER graf tychto zavislosti.

      A. ANNOTATION [@Qualifier] sa aplikuje na SPRING MANAGED BEAN. Vdaka tejto aplikacii su SPRING MANAGED BEANS priradene unikatne IDENTIFIERS.

   !!! E. PROGRAM moze definovat aj CUSTOM ANNOTATIONS, na ktore su aplikovane ANNOTATION [@Qualifier] na identifikaciu SPRING MANAGED BEANS. Je mozne pouzit nasledujuce postupy.
      A. Pre kazdy SPRING MANAGED BEAN sa definuje vlastna CUSTOM ANNOTATION. Tieto CUSTOM ANNOTATIONS priradia kazdej SPRING MANAGED BEAN unikatny IDENTIFIER, na zaklade ktoreho je mozne konkretny SPRING MANAGED BEAN priradit pre dany DEPENDENCY INJECTION.
      B. Pre vsetky SPRING MANAGED BEANS sa definuje 1 CUSTOM ANNOTATION, ktory ma definovany IDENTIFIER ELEMENT na zaklade, ktoreho sa definuje unikatny IDENTIFIER daneho BEAN, na zaklade ktoreho je mozne konkretny SPRING MANAGED BEAN priradit pre dany DEPENDENCY INJECTION.
41. SPRING FRAMEWORK umoznuje definovat SPRING MANAGED BEANS ako PRIMARY BEANS. Platia nasledujuce fakty.
   A. PRIMARY SPRING MANAGED BEAN je SPRING MANAGED BEAN, ktory sa pouzije ako DEFAULT SPRING MANAGED BEAN, ak existuje viacero SPRING MANAGED BEANS, ktore je mozne pre danu DEPENDENCY INJECTION mozne substituovat. To znamena, ze ak SPRING FRAMEWORK zisti, ze existuje viacero SPRING MANAGED BEANS, ktore moze substituovat pre danu DEPENDENCY INJECTION, co by sposobil TYPE AMBIGUITY, ale jeden z tychto SPRING MANAGED BEANS je oznaceny ako PRIMARY SPRING MANAGED BEAN, SPRING FRAMEWORK pouzije pre danu DEPENDENCY INJECTION PRIMARY SPRING MANAGED BEAN.
   B. PRIMARY SPRING MANAGED BEAN, ktory je oznaceny pomocou ANNOTATION [@Primary].
   !!! C. SPRING FRAMEWORK NEUMOZNUJE oznacit viacero SPRING MANAGED BEANS rovnakeho TYPE ako PRIMARY SPRING MANAGED BEANS.
42. SPRING FRAMEWORK umoznuje ziskat viacero, alebo aj vsetky instancie SPRING MANAGED BEANS pomocou DEPENDENCY INJECTION. Platia nasledujuce fakty.
   A. Ak existuje DEPENDENCY na COLLECTION SPRING MANAGED BEANS, pricom samotny COLLECTION TYPE nie je definovany ako SPRING MANAGED BEAN, potom SPRING FRAMEWORK substituje danu DEPENDENCY za vsetky SPRING MANAGED BEANS pre ktore existuje pre danu DEPENDENCY MATCH.
   B. Mapovanie COLLECTIONS SPRING MANAGED BEANS umoznuje ziskat vsetky SPRING MANAGED BEANS pre ktore existuje MATCH pre danu DEPENDENCY.
   C. Mapovanie COLLECTIONS SPRING MANAGED BEANS ma nasledujuce podmienky.
      A. SPRING MANAGED BEAN musi mat DEPENDENCY na COLLECTION SPRING MANAGED BEANS. Ako COLLECTION TYPE je mozne pouzit ARRAY, LIST TYPES, alebo SET TYPES.
      B. SPRING MANAGED BEANS COLLECTION TYPE NESMIE byt definovany ako samostatny SPRING MANAGED BEAN.
   D. Mapovanie COLLECTIONS SPRING MANAGED BEANS umoznuje aj mapovanie na MAPS. Platia nasledujuce fakty.
      A. MAP musi byt MAP TYPE, ktora ma ako KEY TYPE [String] a VALUE TYPE je TYPE daneho SPRING MANAGED BEAN.
      B. SPRING FRAMEWORK naplni MAP TYPE KEY VALUE VALUES, kde KEY obsahuje nazov SPRING MANAGED BEAN a VALUE obsahuje samotny SPRING MANAGED BEAN.
   E. Mapovanie COLLECTIONS SPRING MANAGED BEANS umoznuje aj FILTERING. Pre FILTERING platia nasledujuce fakty.
      A. FILTERING umoznuje do COLLECTION SPRING MANAGED BEANS ulozit iba tie SPRING MANAGED BEANS na ktore maju identicky IDENTIFIER.
      B. FILTERING vyuziva IDENTIFIERS z ANNOTATION [@Qualifier], ktoru je nutne aplikovat ako na dane SPRING MANAGED BEANS tak aj na COLLECTION SPRING MANAGED BEANS DEPENDECY na ktoru sa ma aplikovat dany FILTERING.
      C. Pri FILTERING SPRING FRAMEWORK ulozi do DEPENDECY na COLLECTION SPRING MANAGED BEANS ulozi iba tie SPRING MANAGED BEANS, ktore maju IDENTIFIER definovany v ANNOTATION [@Qualifier].
43. SPRING FRAMEWORK umoznuje urcovat, ktory SPRING MANAGED BEAN sa ma pri DEPENDENCY INJECTION substituovat pomocou NAMING CONVENTION nazyvanym aj FALLBACK MATCH. Pre DEPENDENCY INJECTION pomocou FALLBACK MATCH platia nasledujuce fakty.
   A. FALLBACK MATCH umoznuje vykonat substituciu FIELDS a PARAMETERS pri DEPENDENCY INJECTION pomocou nazvov FIELDS a PARAMETERS, ktore ma substituovat.
   B. Pri FALLBACK MATCH ak pre dany FIELD, alebo PARAMETER v DEPENDENCY INJECTION existuje viacero SPRING MANAGED BEANS, ktore by mohli byt substituovane a doslo by k TYPE AMBIGUITY, SPRING FRAMEWORK zisti, ci NAME daneho FIELD, alebo PARAMETER nie je zhodny s SPRING MANAGED BEAN NAME. Ak ano, vyberie tento SPRING MANAGED BEAN pre substituciu v danej DEPENDENCY INJECTION.
   C. FALLBACK MATCH je mozne pouzit pre CONSTRUCTOR INJECTION, SETTER INJECTION aj FIELD INJECTION.
   !!! D. FALLBACK MATCH sa NEODPORUCA pouziva, pretoze je ERROR PRONE. Pri zmene nazvu SPRING MANAGED BEAN bez zmeny nazvu FIELD alebo PARAMETER dojde k znefunkcneniu FALLBACK MATCH.
44. DEPENDENCY INJECTION je mozne vykonavat aj pomocou ANNOTATION [@Resource]. Platia nasledujuce fakty.
   A. Pri pouziti ANNOTATION [@Resource] su SPRING MANAGED BEANS vyhladavana na zaklade NAME, ktory je definovany v ELEMENT [name] ANNOTATION [@Resource].
   B. ANNOTATION [@Resource] musi byt aplikovana na samotny na DEPENDENCY, ktora ma byt pomocou DEPEDENCY INJECTION RESOLVED. Takato DEPENDECY je nasledne RESOLVED IBA na zaklade SPRING MANAGED BEAN NAME.
   !!! C. Pri pouziti ANNOTATION [@Resource] TYPE danej DEPENDENCY NEHRA pre RESOLVING ZIADEN VYZNAM. Kludne moze byt TYPE danej DEPENDENCY TYPE [Object].
   !!! D. Ak v ANNOTATION [@Resource] NIE je nastavena VALUE ELEMENT [name], tak SPRING FRAMEWORK zoberie nazov DEPENDENCY (SETTER PARAMETER, alebo FIELD NAME) a pouzije ho na vyhladanie SPRING MANAGED BEAN.
   !!! E. ANNOTATION [@Resource] NIE je mozne pouzit pre CONSTRUCTOR DEPENDENCY.
   F. ANNOTATION [@Resource] je mozne pouzit pre FIELD DEPENDENCY.
   !!!!! G. ANNOTATION [@Resource] je mozne pouzit pre SETTER DEPENDENCY, ale SETTER MUSI byt KLASICKY JAVA SETTER, ktory ma iba 1 PARAMETER a nie SETTER METHOD, ktore standardne SPRING FRAMEWORK pre ine typy riesenia DEPENDENCY INJECTION podporuje.
   H. Pouzitie ANNOTATION [@Resource] NEVYZADUJE aplikaciu ANNOTATION [@Autowired] na FIELD ci SETTER.
45. SPRING FRAMEWORK umoznuje ziskavat instancie SPRING MANAGED BEANS programovo pomocou INTERFACE [ObjectProvider<T>]. Pre INTERFACE [ObjectProvider<T>] platia nasledujuce fakty.
   A. INTERFACE umoznuje PROGRAMOVO ziskavat instancie SPRING MANAGED BEANS zo SPRING CONTAINER.
   B. Instanciu INTERFACE je mozne ziskat nasledujucimi sposobmi.
      A. Pomocou DEPENDENCY INJECTION.
      B. Volanim METHOD [<T> ObjectProvider<T> BeanFactory.getBeanProvider(Class<T> requiredType)]. INTERFACE [BeanFactory] je implementovany SPRING CONTAINER OBJECT.
   !!! C. INTERFACE [ObjectProvider<T>] implementuje INTERFACE [ObjectFactory<T>], ktora definuje METHOD [T getObject() throws BeansException], ktora v DEFAULT IMPLEMENTATION ziskava instancie SPRING MANAGED BEANS zo SPRING CONTAINER.
   D. INTERFACE [ObjectProvider<T>] ma nasledujuce MEMBERS.
      A. METHOD [T ObjectFactory<T>.getObject() throws BeansException] je zdedena z INTERFACE [ObjectFactory<T>] a vybera instanciu SPRING MANAGED BEAN zo SPRING CONTAINER. METHOD vykonava nasledujucu cinnost.
         A. Ak METHOD najde v SPRING CONTAINER presne 1 instanciu SPRING MANAGED BEAN, vrati ho.
         B. Ak METHOD NENAJDE v SPRING CONTAINER ziadnu instanciu SPRING MANAGED BEAN, hodi EXCEPTION [NoSuchBeanDefinitionException].
         C. Ak METHOD NAJDE v SPRING CONTAINER VIACERO instancii SPRING MANAGED BEANS, hodi EXCEPTION [NoUniqueBeanDefinitionException].
      B. DEFAULT METHOD [T getObject(@Nullable Object... args) throws BeansException] vykonava nasledujucu cinnost.
         A. METHOD vola METHOD [<T> T BeanFactory.getBean(Class<T> requiredType) throws BeansException] INTERFACE [BeanFactory].
         B. Ak instancia SPRING MANAGED BEAN existuje, vrati ju.
         !!! C. Ak instancia SPRING MANAGED BEAN NEEXISTUJE, pricom SPRING MANAGED BEAN ma PROTOTYPE SCOPE, METHOD vytvori instanciu SPRING MANAGED BEAN s pouzitim PARAMETERS, ktore zasle do CONSTRUCTOR, alebo FACTORY METHOD daneho SPRING MANAGED BEAN.
         D. Ak instancia SPRING MANAGED BEAN NEEXISTUJE, pricom SPRING MANAGED BEAN NEMA PROTOTYPE SCOPE, METHOD hodi EXCEPTION.
      C. DEFAULT METHOD [@Nullable T getIfAvailable() throws BeansException] vykonava nasledujucu cinnost.
         A. Ak instancia SPRING MANAGED BEAN existuje, vrati ju.
         B. Ak instancia SPRING MANAGED BEAN neexistuje, vrati VALUE [null].
         C. Ak existuje viac ako 1 instancia SPRING MANAGED BEAN, METHOD hodi EXCEPTION [NoUniqueBeanDefinitionException].
      D. DEFAULT METHOD [default T getIfAvailable(Supplier<T> defaultSupplier) throws BeansException] vykonava nasledujucu cinnost.
         A. METHOD zavola METHOD [@Nullable T getIfAvailable() throws BeansException].
         B. Ak METHOD [@Nullable T getIfAvailable() throws BeansException] vratila VALUE [null], zavola sa METHOD [T Supplier<T>.get()] INTERFACE [Supplier<T>] a vysledok volania sa vrati ako RETURN VALUE.
      E. DEFAULT METHOD [void ifAvailable(Consumer<T> dependencyConsumer) throws BeansException] vykonava nasledujucu cinnost.
         A. Ak instancia SPRING MANAGED BEAN existuje, pre danu instanciu zavola METHOD [void Consumer<T>.accept(T t)] INTERFACE [Consumer<T>].
         B. Ak instancia SPRING MANAGED BEAN neexistuje, METHOD skonci.
         C. Ak existuje viac ako 1 instancia SPRING MANAGED BEAN, METHOD hodi EXCEPTION [NoUniqueBeanDefinitionException].
      F. DEFAULT METHOD [@Nullable T getIfUnique() throws BeansException] vykonava nasledujucu cinnost.
         A. Ak existuje 1 instancia SPRING MANAGED BEAN, METHOD ju vrati.
         B. Ak existuje 0, alebo N instancii SPRING MANAGED BEANS, METHOD vrati VALUE [null].
      G. DEFAULT METHOD [T getIfUnique(Supplier<T> defaultSupplier) throws BeansException] vykonava nasledujucu cinnost.
         A. METHOD zavola METHOD [@Nullable T getIfUnique() throws BeansException].
         B. Ak METHOD [@Nullable T getIfUnique() throws BeansException] vratila VALUE [null], zavola sa METHOD [T Supplier<T>.get()] INTERFACE [Supplier<T>] a vysledok volania sa vrati ako RETURN VALUE.
      H. DEFAULT METHOD [void ifUnique(Consumer<T> dependencyConsumer) throws BeansException] vykonava nasledujucu cinnost.
         A. METHOD zavola METHOD [@Nullable T getIfUnique() throws BeansException].
         B. Ak METHOD [@Nullable T getIfUnique() throws BeansException] vratila instanciu SPRING MANAGED BEAN, pre danu instanciu zavola METHOD [void Consumer<T>.accept(T t)] INTERFACE [Consumer<T>].
      I. DEFAULT METHOD [Iterator<T> iterator()] vracia ITERATOR, ktorym je mozne iterovat vsetkymi instanciami SPRING MANAGED BEANS.
      J. DEFAULT METHOD [Stream<T> stream()] vracia STREAM, ktorym je mozne iterovat vsetkymi instanciami SPRING MANAGED BEANS.
      K. DEFAULT METHOD [Stream<T> orderedStream()] vracia ORDERED STREAM, ktorym je mozne iterovat vsetkymi instanciami SPRING MANAGED BEANS, ktore su ORDERED na zaklade hodnoty ANNOTATION [@Order].
46. Ak SPRING FRAMEWORK vykonava DEPENDENCY INJECTION VSETKYCH SPRING MANAGED BEANS daneho TYPE (napriklad do COLLECTION TYPE PARAMETERS), SPRING FRAMEWORK umoznuje definovat poradia v akom budu tieto SPRING MANAGED BEANS ulozene v COLLECTION PARAMETER. Platia nasledujuce fakty.
   A. ORDER urcuje poradie v akom budu SPRING MANAGED BEANS daneho TYPE ukladane do COLLECTION TYPE PARAMETERS pri DEPENDENCY INJECTION.
   B. ORDER je urceny INTEGER VALUE, pricom plati, ze NIZSIA VALUE daneho ORDER znamena VYSSIU PRIORITU.
   C. ORDER moze obsahovat aj ZAPORNE hodnoty.

   E. ORDER pre SPRING MANAGED BEAN je mozne definovat nasledujucimi sposobmi.

47. V SPRING MANAGED BEANS sa aplikuje INHERITANCE nasledujucim sposobom.
   A. ANNOTATION [@Bean] JE INHERITED. To znamena, ze aj CONFIGURATION CLASS ma PARENT CLASS obsahujuci FACTORY METHODS, alebo PARENT INTERFACES, ktore obsahuju FACTORY DEFAULT METHODS, tak tieto METHODS su INHERITED do DERIVED CLASS a FACTORY METHODS su volane a prislusne SPRING MANAGED BEANS su vlozene do SPRING CONTAINER.
   B. ANNOTATION [@Component] NIE JE INHERITED. To znamnena, ze ak na BASE CLASS je aplikovana ANNOTATION [@Component], tak na DERIVED CLASS NIE JE automaticky aplikovana tato ANNOTATION a DERIVED CLASS sa tym padom NESTAVA AUTOMATICKY SPRING MANAGED BEAN. Je to preto, lebo ANNOTATION [@Component] NEMA aplikovanu ANNOTATION [@Inherited], ktora by takuto INHERITANCE sposobila.
   C. Pre ANNOTATION [@Autowired] platia nasledujuce fakty.
      A. Ak sa ANNOTATION [@Autowired] aplikuje v BASE CLASS SPRING MANAGED BEAN, tak SPRING FRAMEWORK vykona DEPENDENCY INJECTION pre BASE CLASS.
      !!! B. Ak je ANNOTATION [@Autowired] aplikovana na SETTER v BASE CLASS, a tento SETTER je OVERRIDEN v DERIVED CLASS, tak ANNOTATION [@Autowired] NIE JE INHERITED a v OVERRIDEN METHOD NEDOJDE k rieseniu DEPENDENCY INJECTION, ak OVERRIDEN METHOD nie je tiez explicitne oznacena pomocou ANNOTATION [@Autowired].
48. SPRING FRAMEWORK umoznuje vyjadrit DEPENDENCIES medzi SPRING MANAGED BEANS explicitne pomocou ANNOTATION [@DependsOn]. Pre ANNOTATION [@DependsOn] platia nasledujuce fakty.
   A. ANNOTATION [@DependsOn] umoznuje definovat zoznam SPRING MANAGED BEANS, na ktorych je dany SPRING MANAGED BEAN zavisly.
   B. ANNOTATION [@DependsOn] sa aplikuje vtedy, ak DEPENDENCIES medzi SPRING MANAGED BEANS nie je mozne vyjadrit IMPLICITNE pomocou DEPENDENCY INJECTION a ANNOTATION [@Autowired].
   C. ANNOTATION [@DependsOn] moze byt aplikovany ako na COMPONENT TYPES, tak aj na FACTORY METHODS.
   !!!!! D. SPRING FRAMEWORK pri ziskavani SPRING MANAGED BEANS zo SPRING CONTAINER volanim METHODS ako je METHOD [<T> T BeanFactory.getBean(Class<T> requiredType) throws BeansException] vytvara instanciu SPRING MANAGED BEAN, ak neexistuje. Spolahlivy sposob ako zistit ci instancia SPRING MANAGED BEAN existuje bez toho, aby bola okamzite vytvorena vyzaduje vykonanie nasledujucich krokov.
      A. Ziska sa instancia SPRING MANAGED BEAN [ApplicationContext].
      B. Zavola sa METHOD [AutowireCapableBeanFactory ApplicationContext.getAutowireCapableBeanFactory() throws IllegalStateException] na ziskanie instancie SPRING MANAGED BEAN [DefaultListableBeanFactory].
      C. Zavola sa METHOD [public boolean DefaultSingletonBeanRegistry.containsSingleton(String beanName)], ktora vrati informaciu ci SPRING MANAGED BEAN uz bol zavedeny, bez toho, aby bol automaticky zavedeny, ak este zavedeny nebol.
49. SPRING FRAMEWORK podporuje LAZY LOADING SPRING MANAGED BEANS. Pre LAZY LOADING SPRING MANAGED BEANS platia nasledujuce fakty.
   A. BY-DEFAULT su SPRING MANAGED BEANS vytvarane pomocou principu EAGER LOADING, ked vsetky pri starte SPRING CONTAINER su vsetky SPRING MANAGED BEANS okamzite vytvorene.
   B. EAGER LOADING vedie k pomalsiemu startu PROGRAMU, no dava istotu, ze vsetky SPRING MANAGED BEANS boli po starte uspesne vytvorene a pri behu PROGRAMU nedojde k chybe pri vytvarani SPRING MANAGED BEANS.
   C. SPRING MANAGED BEAN moze byt oznaceny aby bol zavedeny pomocou LAZY LOADING aplikovanim ANNOTATION [@Lazy]. Pre ANNOTATION [@Lazy] platia nasledujuce fakty.
      A. ANNOTATION [@Lazy] umoznuje oznacit ci SPRING MANAGED BEAN ma byt zavedeny pomocou LAZY LOADING, alebo EAGER LOADING.
      B. ANNOTATION [@Lazy] ma ELEMENT [value], ktora ak je nastavena na VALUE [true], tak SPRING MANAGED BEAN bude zavedena pomocou LAZY LOADING a ak je nastavena na VALUE [false], tak SPRING MANAGED BEAN bude zavedena pomocou EAGER LOADING.
      !!! C. ANNOTATION [@Lazy] moze byt aplikovana na TYPES, METHODS, CONSTRUCTORS, PARAMETERS a FIELDS. To znamena, ze ANNOTATION [@Lazy] moze byt aplikovana ako na CONFIGURATION TYPES, tak aj na FACTORY METHODS. ANNOTATION [@Lazy] aj pri AUTOWIRING v INJECTION POINTS.
      !!! D. Nastavenie ANNOTATION [@Lazy] na CHILD JAVA ELEMENT prepise nastavenie ANNOTATION [@Lazy] na PARENT JAVA ELEMENT. To znamena, ze ak napriklad na CONFIGURATION TYPE je aplikovana ANNOTATION [@Lazy(true)] vyzadujuca, aby vsetky MANAGED BEANS definovane v tomto CONFIGURATION TYPE boli zavedene pomocou LAZY LOADING, ak je na niektoru FACTORY METHOD aplikovana ANNOTATION [@Lazy(false)], tak tento SPRING MANAGED BEAN bude zavedeny pomocou EAGER LOADING.
   !!!!! D. Interne LAZY LOADING SPRING MANAGED BEANS je implementovany tak, ze pre SPRING MANAGED BEAN, ktory je oznaceny, aby bol zavedeny pomocou LAZY LOADING vytvori SPRING FRAMEWORK PROXY OBJECT. Ak PROGRAM prvykrat pristupi k tomuto PROXY OBJECT, SPRING FRAMEWORK automaticky vytvori instanciu SPRING MANAGED BEAN.
   E. BY DEFAULT SPRING FRAMEWORK pouziva EAGER LOADING. Tento SETTING je mozne zmenit volanim METHOD [void SpringApplication.setLazyInitialization(boolean lazyInitialization)].
50. V SPRING FRAMEWORK moze dojst k BEAN INITIALIZATION PROBLEM. Pre BEAN INITIALIZATION PROBLEM platia nasledujuce fakty.
   A. Pri vytvarani instancii SPRING MANAGED BEANS, SPRING FRAMEWORK vykonava AUTOWIRING v nasledujucom poradi.
      !!! A. Zavola sa CONSTRUCTOR daneho TYPE. CONSTRUCTOR sa vola bez ohladu na to ci je oznaceny pomocou ANNOTATION [@Autowired], alebo nie.
      B. Vykona sa AUTOWIRING vsetkych AUTOWIRED FIELDS.
      C. Vykona sa AUTOWIRING vsetkych AUTOWIRED SETTERS.
   !!! B. Pre BEAN INITIALIZATION PROBLEM vznika vtedy, ak sa CODE v CONSTRUCTOR SPRING MANAGED BEAN pokusi pristupit k instancii SPRING MANAGED BEAN, ktora je AUTOWIRED pomocou FIELD, alebo SETTER. Kedze CONSTRUCTOR daneho SPRING MANAGED BEAN je volany PRED vykonanim FIELDS AUTOWIRING a SETTERS AUTOWIRING, su v CONSTRUCTOR tieto instancie SPRING MANAGED BEANS nastavene na VALUE [null].
   C. Riesenim je, ze ak CONSTRUCTOR potrebuje vyuzit SPRING MANAGED BEANS, ktore su AUTOWIRED pomocou FIELDS, alebo SETTERS, je lepsie nahradi FIELDS AUTOWIRING a SETTERS AUTOWIRING za CONSTRUCTORS AUTORIWING.
51. SPRING FRAMEWORK definuje CALLBACK METHODS, ktore su volane pocas LIFECYCLE daneho SPRING MANAGED BEAN. Tieto CALLBACK METHODS na nazyvaju LIFECYCLE CALLBACKS. Pre LIFECYCLE CALLBACKS platia nasledujuce fakty.
   A. LIFECYCLE CALLBACKS su EVENTS, ktore volane pocas zivotnosti SPRING MANAGED BEANS, umoznujuc ich CUSTOMIZATION.
   B. LIFECYCLE CALLBACKS je mozne definovat nasledujucimi sposobmi.
      A. Definovanim METHODS v SPRING MANAGED BEAN TYPES, ktore su oznacene prislusnymi ANNOTATIONS.
      B. Implementovanim INTERFACES zo strany SPRING MANAGED BEAN TYPES, ktorych METHODS reprezentuju prislusne LIFECYCLE CALLBACKS.
52. Pre definovanie LIFECYCLE CALLBACKS pomocou ANNOTATIONS platia nasledujuce fakty.
   A. SPRING FRAMEWORK definuje nasledujuce ANNOTATIONS, ktorymi je mozne oznacit METHODS za LIFECYCLE CALLBACKS.
      A. ANNOTATION [@PostConstruct] definuje LIFECYCLE CALLBACK volany po inicializacii SPRING MANAGED BEAN. Pri volani tejto LIFECYCLE CALLBACK je dany SPRING MANAGED BEAN plne inicializovany a vsetky AUTOWIRINGS su vykonane.
      B. ANNOTATION [@PreDestroy] definuje LIFECYCLE CALLBACK volany pred uvolnenim SPRING MANAGED BEAN. Interne je tato LIFECYCLE CALLBACK implementovana pomocou SHUTDOWN HOOKS, ktore su volane aj v pripade, ze sa vola METHOD [void System.exit(int status)].
   B. LIFECYCLE CALLBACKS musia byt definovane ako NON-STATIC MEMBER METHODS SPRING MANAGED BEAN pre ktory sa maju volat.
   C. LIFECYCLE CALLBACKS standardne NEMAJU PARAMETERS, okrem JAKARTA ENTERPRISE BEANS INTERCEPTORS, ktore su OPTIONAL.
   D. LIFECYCLE CALLBACKS nemaju ziadnu RETURN VALUE.
   E. LIFECYCLE CALLBACKS NESMU hodit CHECKED EXCEPTIONS. Mozu vsak hodit UNCHECKED EXCEPTIONS.
   F. LIFECYCLE CALLBACKS su volane pomocou REFLECTION, takze ich VISIBILITY NIE je dolezita.
   G. LIFECYCLE CALLBACKS su INHERITED a teda su volane aj pre INHERITED SPRING MANAGED BEANS, ak su tieto LIFECYCLE CALLBACKS v BASE CLASSES ci v BASE INTERFACES, ako DEFAULT METHODS.
   !!! H. Pre SPRING MANAGED BEANS vytvarane pomocou ANNOTATION [@Bean] su LIFECYCLE CALLBACKS su definovane nasledujucim sposobom.
      A. ANNOTATION [@Bean] obsahuje ELEMENT [initMethod], ktora umoznuje definovant POST CONSTRUCT LIFECYCLE CALLBACK. METHOD musi byt definovana v SPRING MANAGED BEAN TYPE.
      B. ANNOTATION [@Bean] obsahuje ELEMENT [destroyMethod], ktora umoznuje definovant PRE DESTROY LIFECYCLE CALLBACK. METHOD musi byt definovana v SPRING MANAGED BEAN TYPE.
      !!!!! C. Ak v ANNOTATION [@Bean] NIE JE nastaveny ELEMENT [destroyMethod], tak SPRING FRAMEWORK postupuje nasledujucim sposobom.
         A. SPRING FRAMEWORK hlada ci v SPRING MANAGED BEAN TYPE nie je definovana METHOD [void close()]. Ak ano, tak ju zavola ako PRE DESTROY LIFECYCLE CALLBACK.
         B. Ak METHOD [void close()] nebola definovana, tak SPRING FRAMEWORK hlada ci v SPRING MANAGED BEAN TYPE nie je definovana METHOD [void shutdown()]. Ak ano, tak ju zavola ako PRE DESTROY LIFECYCLE CALLBACK.
         C. Ak SPRING MANAGED BEAN TYPE definuje METHOD [void close()] aj METHOD [void shutdown()], tak sa vola IBA METHOD [void close()].
      !!! D. METHOD [void close()] aj METHOD [void shutdown()] MUSIA byt PUBLIC METHODS definovane v prislusnom SPRING MANAGED BEAN TYPE.
53. Pre definovanie LIFECYCLE CALLBACKS pomocou INTERFACES platia nasledujuce fakty.
   A. SPRING FRAMEWORK definuje nasledujuce INTERFACES, ktorymi je mozne oznacit METHODS za LIFECYCLE CALLBACKS.
      A. INTERFACE [InitializingBean], ktory definuje METHOD [void afterPropertiesSet() throws Exception]. Pri volani tejto LIFECYCLE CALLBACK je dany SPRING MANAGED BEAN plne inicializovany a vsetky AUTOWIRINGS su vykonane.
      B. INTERFACE [DisposableBean], ktory definuje METHOD [void destroy() throws Exception]. METHOD je volana pred uvolnenim SPRING MANAGED BEAN.
   B. SPRING MANAGED BEAN, ktory chce zachytavat LIFECYCLE CALLBACKS musi implementovat prislusne INTERFACES.

66. SPRING EXPRESSION LANGUAGE (SPEL) je EXPRESSION LANGUAGE pre OBJECT QUERYING a OBJECT MANIPULATION v RUNTIME. Pre SPRING EXPRESSION LANGUAGE platia nasledujuce fakty.
   A. SPRING EXPRESSION LANGUAGE umoznuje definovat EXPRESSIONS, ktore mozu byt definovane DEKLARATIVNE a mozu vykonavat OPERATIONS nad OBJECTS.
   B. SPRING EXPRESSION LANGUAGE umoznuje definovat EXPRESSIONS DEKLARATIVNE napriklad v ANNOTATIONS ci XML CONFIGURATION FILES a nasledne pomocou SPRING EXPRESSION LANGUAGE su tieto EXPRESSIONS vykonane.
   C. SPRING EXPRESSION LANGUAGE podporuje nasledujuce typy OPERATIONS.
      A. ARITHMETIC OPERATORS.
      B. LOGICAL OPERATORS ako OPERATOR [and] OPERATOR [or] a OPERATOR [not].
      C. CONDITIONAL OPERATOR.
      D. STRING OPERATIONS, ktore su definovane v JAVA CLASS [String]. STRINGS v SPRING EXPRESSION LANGUAGE su definovane pomocou SYNTAXE ['STRING_VALUE'], kde VALUE [STRING_VALUE] je VALUE daneho STRING.
      E. Vytvaranie instancii JAVA CLASSES pomocou OPERATOR NEW.
      F. Pristup k PROPERTIES JAVA CLASSES pomocou SYNTAX [OBJECT.PROPERTY_NAME], kde VALUE [OBJECT] je JAVA OBJECT IDENTIFIER a VALUE [PROPERTY_NAME] je nazov PROPERTY. Pre takuto EXPRESSION SPRING EXPRESSION LANGUAGE PROPERTY automaticky EXPRESSION SPRING EXPRESSION LANGUAGE vola prislusnu GETTER METHOD.
      G. Pracu s instanciami JAVA CLASS [List<TType>]. Platia nasledujuce fakty.
         A. Instancia JAVA CLASS [List<TType>] sa vytvara pomocou SYNTAX [{VALUE_1,...,VALUE_N}}], kde VALUES [VALUE_X] reprezentuju VALUES daneho LIST.
         B. Vykonavanim OPERATIONS nad instanciou JAVA CLASS [List<TType>]. Napriklad CODE [{1,2,3,4}.get(0)] vytvori instanciu JAVA CLASS [List<int>] a pristupi k 1. ITEM v tomto LIST.
      H. Vykonavanie REGULAR EXPRESSION pomocou SYNTAX [STRING_VALUE matches REGULAR_EXPRESSION], kde VALUE [STRING_VALUE] je STRING VALUE a VALUE [REGULAR_EXPRESSION] je REGULAR EXPRESSION, ktory ma byt nad STRING VALUE vykonany.
      I. Pristup k STATIC METHODS pomocou SYNTAX ["T(CLASS_TYPE).METHOD_NAME(PARAMETER_1,...,PARAMETER_N)], kde VALUE [CLASS_TYPE] je nazov CLASS TYPE, VALUE [METHOD_NAME] je nazov STATIC METHOD NAME a VALUES [PARAMETER_X] su PARAMETERS STATIC METHOD.
      !!!!! J. Pouzitie OPERATOR [@], ktory umoznuje referovat sa na instanciu SPRING MANAGED BEAN. Pri pouziti OPERATOR [@] je nutne spustit nasledujuci CODE.
         A. Zo SPRING CONTAINER sa ziska instancia CLASS [BeanFactory].
         B. Vytvori sa instancia CLASS [ExpressionParser].
         C. Vytvori sa instancia CLASS [StandardEvaluationContext].
         D. Vytvori sa instancia CLASS [BeanFactoryResolver] pricom do CONSTRUCTOR sa zada instancia CLASS [BeanFactory].
         E. Volanim METHOD [void StandardEvaluationContext.setBeanResolver(@Nullable BeanResolver beanResolver)] sa nastavi instancia CLASS [BeanFactoryResolver] v CLASS [StandardEvaluationContext].
         F. Zavola sa METHOD [Expression ExpressionParser.parseExpression(String expressionString) throws ParseException], ktora vrati instanciu CLASS [Expression].
         G. Zavola sa METHOD [Object Expression.getValue(EvaluationContext context) throws EvaluationException], ktora vykona SPRING EXPRESSION LANGUAGE EXPRESSION s pouzitym OPERATOR [@].
   D. SPRING EXPRESSION LANGUAGE PARSER je implementovany v CLASS [SpelExpressionParser], ktora implementuje INTERFACE [ExpressionParser]. INTERFACE [ExpressionParser] ma nasledujuce METHODS.
      A. METHOD [Expression parseExpression(String expressionString) throws ParseException] vykona PARSING danej SPRING EXPRESSION LANGUAGE EXPRESSION.
      B. METHOD [Expression parseExpression(String expressionString, ParserContext context) throws ParseException] vykona PARSING danej SPRING EXPRESSION LANGUAGE EXPRESSION s definovanym CONTEXT.
   E. INTERFACE [Expression] obsahuje PARSED SPRING EXPRESSION LANGUAGE EXPRESSION. Ma nasledujuce MEMBERS.
