1. Solution demonstruje pouzitie FILESYSTEM LIBRARY v C++.
2. FILESYSTEM LIBRARY je definovana v LIBRARY [filesystem].
3. FILESYSTEM LIBRARY je definovana v NAMESPACE [std::filesystem].
4. FILESYSTEM LIBRARY je postavena na nasledujucich principoch.
   A. FILESYSTEM LIBRARY je postavena na POSIX standardoch.
   B. Ak danu FILESYSTEM LIBRARY OPERATION je mozne pre dany OPERATING SYSTEM implementovat, tak by ju FILESYSTEM LIBRARY ju mala implementovat.
   C. Ak danu FILESYSTEM LIBRARY OPERATION NIE je mozne pre dany OPERATING SYSTEM implementovat, tak FILESYSTEM LIBRARY by mala vratit ERROR.
5. Funkcionalita FILESYSTEM PATH je implementovana pomocou CLASS [path]. Pre FILESYSTEM PATHS platia nasledujuce fakty.
   A. PATH reprezentuje FILE LOCATION vo FILESYSTEM.
   B. PATH je tvoreny nasledujucimi ELEMENTS.
      A. OPTIONAL ROOT NAME.
      B. OPTIONAL ROOT DIRECTORY.
      C. Sekvenciou FILE NAMES, ktore su oddelene pomocou DIRECTORY SEPARATORS.
   C. PATH moze byt nasledujucich typov.
      A. ABSOLUTE PATH. ABSOLUTE PATH je plna PATH, ktora nezavisi na hodnote CURRENT DIRECTORY.
       B. RELATIVE PATH. RELATIVE PATH je ciastocna PATH, ktora zavisi na hodnote CURRENT DIRECTORY.
   D. CLASS [path] podporuje nasledujuce PATH FORMATSS.
      A. GENERIC PATH FORMAT. Pre GENERIC PATH FORMAT platia nasledujuce fakty.
         A. GENERIC PATH FORMAT vychadza z POSIX specifikacie.
         B. GENERIC PATH FORMAT je PORTABLE.
         C. GENERIC PATH FORMAT ma FORMAT [[ROOT_NAME][ROOT_DIRECTORY][RELATIVE_PATH]], kde VALUE [ROOT_NAME] je OPTIONAL ROOT NAME (napriklad VALUE [C:], alebo VALUE [\\host]), VALUE [ROOT_DIRECTORY] je OPTIONAL ROOT DIRECTORY a VALUE [RELATIVE_PATH] je RELATIVE PATH oddelena DIRECTORY SEPARATORS.
      B. NATIVE PATH FORMAT. Pre NATIVE PATH FORMAT platia nasledujuce fakty.
         A. NATIVE PATH FORMAT je specificky pre dany FILESYSTEM a OPERATING SYSTEM.
         B. NATIVE PATH FORMAT NIE je PORTABLE.
   E. PATH definuje nasledujuce SPECIAL FILE NAMES.
      A. SPECIAL FILE NAME [.] definuje CURRENT DIRECTORY.
      B. SPECIAL FILE NAME [..] definuje PARENT DIRECTORY.
   F. PATH moze obsahovat DIRECTORY SEPARATORS. Pre DIRECTORY SEPARATORS platia nasledujuce fakty.
      A. DIRECTORY SEPARATOR je tvoreny jednym, alebo viacerymi DIRECTORY SEPARATOR CHARACTERS.
      B. DIRECTORY SEPARATOR CHARACTER moze obahovat nasledujuce VALUE.
         A. VALUE [/] je GENERIC FORMAT DIRECTORY SEPARATOR CHARACTER.
         B. Ina VALUE, napriklad VALUE [\] vo WINDOWS je PREFERRED IMPLEMENTATION SPECIFIC DIRECTORY SEPARATOR CHARACTER.
   G. CLASS [path] poskytuje METHODS pre konverziu medzi GENERIC PATH FORMAT a NATIVE PATH FORMAT.
   H. CLASS [path] podporuje aj EMTPY PATHS.
   !!! I. PATH moze byt NORMALIZED. NORMALIZATION aplikuje nasledujuce RULES.
      A. Ak PATH je EMPTY, NORMALIZED PATH je EMPTY.
      B. V NORMALIZED PATH su vsetky vyskyty DIRECTORY SEPARATOR CHARACTER [/], ktore sa mozu nachadzat aj opakovane za sebou, nahradene JEDNYM PREFERRED IMPLEMENTATION SPECIFIC DIRECTORY SEPARATOR CHARACTER (napriklad VALUE [\]).
      C. V NORMALIZED PATH su vsetky vyskyty DIRECTORY SEPARATOR CHARACTER [/] v ROOT NAME nahradene PREFERRED IMPLEMENTATION SPECIFIC DIRECTORY SEPARATOR CHARACTER (napriklad VALUE [\]).
      D. V NORMALIZED PATH sa odstrania vsetky vyskyty VALUE [.DIRECTORY_SEPARATOR_CHARACTER], kde VALUE [DIRECTORY_SEPARATOR_CHARACTER] je DIRECTORY SEPARATOR CHARACTER.
      E. V NORMALIZED PATH sa odstrania vsetky vyskyty VALUE [..DIRECTORY_SEPARATOR_CHARACTER___DIRECTORY_NAME___DIRECTORY_SEPARATOR_CHARACTER], kde VALUE [DIRECTORY_SEPARATOR_CHARACTER] je DIRECTORY SEPARATOR CHARACTER a VALUE [DIRECTORY_NAME] je DIRECTORY NAME.
      F. V NORMALIZED PATH, ak PATH obsahuje ROOT DIRECTORY, odstrania sa vsetky vyskyty VALUE [..DIRECTORY_SEPARATOR_CHARACTER], kde VALUE [DIRECTORY_SEPARATOR_CHARACTER] je DIRECTORY SEPARATOR CHARACTER, ktore nasleduju HNED za ROOT DIRECTORY.
      G. V NORMALIZED PATH, je posledny FILE NAME SPECIAL FILE NAME [..], odstrani sa nasledujuci DIRECTORY SEPARATOR CHARACTER ak taky existuje.
      H. Ak je NORMALIZED PATH EMPTY, nastavi sa na SPECIAL FILE NAME [.].
6. FILESYSTEM LIBRARY definuje MEMBER METHODS a FREE STANDING FUNCTIONS. Platia nasledujuce principy.
   A. Ako MEMBER METHODS su implementovanie tie OPERATIONS, ktore NEVYZADUJU vykonavanie narocnych FILESYSTEM OPERATIONS.
   B. Ako FREE STANDING FUNCTIONS su implementovanie tie OPERATIONS, ktore VYZADUJU vykonavanie narocnych FILESYSTEM OPERATIONS.
7. ERROR HANDLING v FILESYSTEM LIBRARY je mozne realizovat nasledujucimi sposobmi.
   A. Volanim OVERLOADED FUNCTIONS, ktore NEMAJU OUTPUT PARAMETER TYPE [error_code]. Taketo FUNCTIONS pri vzniku ERROR hodia EXCEPTION [filesystem_error].
   B. Volanim OVERLOADED FUNCTIONS, ktore MAJU OUTPUT PARAMETER TYPE [error_code]. Taketo FUNCTIONS pri vzniku ERROR hodia NEHODIA EXCEPTION, ale nastavia OUTPUT PARAMETER TYPE [error_code] na ERROR CODE.

   G. METHOD [const path& path2(void) const noexcept] vracia PATH 2, kde doslo k vzniku EXCEPTION.
   H. METHOD [const char* what(void) const noexcept] vracia textovy popis EXCEPTION.
   I. METHOD [const error_code& code(void) const noexcept] vracia ERROR CODE danej EXCEPTION.

Ak je nova PATH ABSOLUTE PATH, tak tato ABSOLUTE PATH kompletne nahradi povodnu PATH. Ak povodna PATH obsahuje ROOT ELEMENT, tak nova PATH je pridana az za ROOT ELEMENT, bud hned za ROOT ELEMENT, ak je nova PATH ABSOLUTE PATH, alebo na koniec povodnej PATH, ak je nova PATH RELATIVE PATH.

Oproti cisto lexikalnemu porovnanie jediny rozdiel je, ze PATHS povazuje za zhodne, ak sa lisia iba v pozicii DIRECTORY SEPARATORS.
   !!!!! 17. NON-MEMBER OPERATOR [OPERATOR/] vytvori novu PATH, ktora vznikne zlucenim 2 PATHS a pridanim DIRECTORY SEPARATOR medzi ne. Ak je PATH na pravej strane OPERATOR [OPERATOR/] ABSOLUTE PATH, tak OPERATOR vrati tuto ABSOLUTE PATH. Ak PATH na lavej strane OPERATOR [OPERATOR/] obsahuje ROOT ELEMENT, tak nova PATH je pridana az za ROOT ELEMENT, bud hned za ROOT ELEMENT, ak je PATH na pravej strane OPERATOR [OPERATOR/] ABSOLUTE PATH, alebo na koniec povodnej PATH, ak je na pravej strane OPERATOR [OPERATOR/] RELATIVE PATH.
   !!! 18. NON-MEMBER OPERATOR [OPERATOR>>] cita textovu reprezentaciu PATH z INPUT STREAM. OPERATOR dokaze citat PATH, ktora moze, ale aj nemusi byt vo formate QUOTED STRING.

62. FUNCTION [void rename(const path& OldPath, const path& NewPath)] vykonava RENAME, alebo MOVE FILES a DIRECTORIES. Platia nasledujuce fakty.
   A. Ak PARAMETER [OldPath] odkazuje na FILE a PARAMETER [NewPath] odkazuje na EXISTING FILE, tak FILE [NewPath] je zmazany, PATH [NewPath] je LINKED na FILE [OldPath] a PATH [OldPath] je UNLIKNED na FILE [OldPath].
   B. Ak PARAMETER [OldPath] odkazuje na FILE a PARAMETER [NewPath] odkazuje na NON-EXISTING FILE, tak PATH [NewPath] je LINKED na FILE [OldPath] a PATH [OldPath] je UNLIKNED na FILE [OldPath].
   C. Ak PARAMETER [OldPath] odkazuje na DIRECTORY a PARAMETER [NewPath] odkazuje na EXISTING DIRECTORY, tak FILE [NewPath] je odstraneny, PATH [NewPath] je LINKED na DIRECTORY PATH [OldPath] je UNLINKED na DIRECTORY.
   D. Ak PARAMETER [OldPath] odkazuje na DIRECTORY a PARAMETER [NewPath] odkazuje na NON-EXISTING DIRECTORY, tak PATH [NewPath] je LINKED na DIRECTORY PATH [OldPath] je UNLINKED na DIRECTORY.

   B. PARAMETER [perm_options Options] ma DEFAULT VALUE [perm_options::replace].
   !!! C. Vo WINDOWS je mozne nastavit iba 2 typy PERMISSIONS a to READ, WRITE a EXECUTE a SEARCH PERMISSIONS pre vsetkych USERS a GROUPS, alebo READ a EXECUTE a SEARCH PERMISSIONS pre vsetkych USERS a GROUPS.

   A. VALUE [replace] znamena, ze existujuce PERMISSIONS sa nahradia novymi PERMISSIONS.
   B. VALUE [add] znamena, ze sa vykona OPERATION [CURRENT_PERMISSIONS | NEW_PERMISSIONS], kde VALUE [CURRENT_PERMISSIONS] su existujuce PERMISSIONS a VALUE [NEW_PERMISSIONS] su nove PERMISSIONS. Teda nove PERMISSIONS sa pridaju k existujucim PERMISSIONS.
   C. VALUE [remove] znamena, ze sa vykona OPERATION [CURRENT_PERMISSIONS & ~(NEW_PERMISSIONS)], kde VALUE [CURRENT_PERMISSIONS] su existujuce PERMISSIONS a VALUE [NEW_PERMISSIONS] su nove PERMISSIONS. Teda nove PERMISSIONS sa odstrania z existujucich PERMISSIONS.
